# 开发者定制指南

AI Carry 的默认体验面向普通用户；开发者可以在不破坏升级通道的前提下扩展。

## 优先使用扩展点

- 新的实例资产放入 `instance/` 对应目录并登记实例地图。
- 平台适配和本地工具保持可删除、可重建，不让其成为正式记忆真源。
- 安装入口由根目录 `INSTALL.md` 正式拥有；`START-HERE.txt` 只负责把当前 Agent 引到它。链接和 ZIP 共用一套结果：完整项目进入新目录、离线看板可打开、随后在看板或当前聊天继续首次创建。首次创建先让用户选择交流方式与方向，再由当前 Agent 渐进访谈并展示完整预览；模型等级只提供能力建议，不是写入票据。用户确认后，确定性执行器只原子写入 manifest、正式档案和领域地图；初始任务只是 `task-family`，不计为资产。启动胶囊、双快照以及验证、候选、组件、宿主和 Skill 等空登记表按首次真正使用的模块延迟初始化。核心中点失败恢复模板；核心成功后的派生项失败只标记局部待重试；第二次相同创建保持幂等。
- 看板扩展遵循动作与快照 Schema；界面不能直接修改正式资产。
- 专业实例需要额外工作区时，使用 `core/schemas/extension-manifest.schema.md` 与 `workspace/<extension-id>/extension.toml` 显式声明便携、派生、设备本地和私密集合引用；空模板不得预装行业内容，普通启动不得枚举 `workspace/**`，未登记工作区必须保留并进入冲突预览。若扩展确有本地网页写入用途，仍保持公共看板只读，只能按深层安全协议临时启用清单登记的 Loopback 写入面。
- 看板的信息架构、视觉、离线构建、电脑窗口适配和验收要求见 [看板设计与前端架构](dashboard-design.md)；新增界面不能绕过其中的数据与动作边界。长页面继续使用原生屏外延迟绘制、绑定 `.app-main` 的可见逐卡进入、单一 Lenis 滚动所有者和滚动期间 Three.js 自动让帧；不能通过叠加滚动库、移除语义 DOM、提前完成进入动画或让预留高度失真来换取表面流畅。
- 修改看板字体或 npm 运行依赖时，必须同步字体清单／OFL 或重新生成生产依赖声明，并让正式离线构建通过本地资源校验；不能只在开发机安装字体、从 CDN 引入资源或把 `node_modules` 当作最终用户依赖。
- 复制或改写 UI 模板、代码片段、图标、图片、模型、数据集等第三方内容时，先按 [开源合规与第三方来源](open-source-compliance.md) 固定官方来源、许可证、版权、修改关系与摘要。`npm run check:compliance` 拒绝未审核许可证和未登记二进制素材，不能通过扩大允许集合来掩盖未知来源。
- AI Carry 自身采用 Apache License 2.0。发布候选必须保留根 `LICENSE`；第三方依赖、改写源码、字体和上游材料仍保留各自许可，并同步维护 `THIRD_PARTY_NOTICES.md`。不能用项目许可证覆盖第三方许可证，也不能在未确认公开版权主体名称时擅自写入维护者个人身份。
- 准备修改任何 AI Carry 正式内容时，先命中 `core/protocols/COMPONENT_CHANGE.md`。模板／核心变更再读取组件地图；实例正式资产同时读取资产生命周期。顺序固定为先修根因、再证明用户数据和使用可靠性、最后减少无意义流程；普通只读和既有资产使用不加载完整协议。
- 所有用户选择都必须保留 `assistant.toml` 的极小交流基线。多步骤、技术性、风险性、长期性或用户不确定的选择由 `core/protocols/USER_GUIDANCE.md` 拥有：先复用 Agent 已知事实，再说明背景、完整选项与后果、推荐依据和“不确定”入口。交流方式只能改变篇幅与节奏。修改任务产出、看板动作、安装、迁移或其他用户流程时，不能退化成要求用户重新提供 Agent 已知路径、填写内部配置或只回答一个含糊问题。
- 修改官方仓库、Release 下载地址或升级入口时，以 `core/upgrade/official-source.toml` 为唯一公开更新来源记录，并同步升级指南、看板动作、README 与目标版本发布清单；不能让 Agent 通过搜索结果或镜像猜测官方版本。README 的最新版 ZIP 由 GitHub 从公开 `main` 自动生成；具体版本升级使用正式固定标签 ZIP，轻量标签和直接指向提交的附注标签都可核验。发布完成时须证明 `main` 与当时 Latest Release 标签同指批准提交，并比较解压后的文件集合与逐文件内容；之后 `main` 前进不会让旧版正式标签失效。GitHub 自动归档的外层 ZIP 摘要不是长期版本身份。
- 维护者本地 Agent／Skill 工具链不是 AI Carry 的运行时、安装材料或可携带资产。正式分发不能依赖或包含这些私密工具；需要复现公开前端或贡献流程时，应由贡献者在自己的环境中安装公开文档列出的依赖。
- 修改 README、安装入口、首次使用文案、看板标题／导航／状态／无障碍标签或 Pages 演示时，必须同步检查 [本地化策略](localization.md)。简体中文仍是默认和内部协议真源；英文只复用同一逻辑与受控产品词库，不复制第二套协议。不得运行时联网翻译，不得自动翻译用户自己的记忆和专业资料，也不得按 IP 或地区猜语言。
- AI Carry 自有中英文内容涉及地域、行政区划、地图、旗帜或国家／地区选择器时，必须按需读取 `core/protocols/TERRITORY_TERMINOLOGY.md`。中文使用“中国台湾、中国香港、中国澳门”，英文使用 `Taiwan, China`、`Hong Kong SAR, China`、`Macao SAR, China`；三者不得作为独立国家展示。用户原话和来源证据保持原文，产品生成的标题、摘要、筛选项和说明使用固定称谓。自动门禁必须通过，地图、旗帜和复杂语境还需要 Level 3 人工复核。

## 同步架构文档

- 整体目标、参与者职责、跨 Agent 语义或正式资产关系发生变化时，同步更新 [架构与设计原则](architecture.md)。
- 涉及时间、次数、风险、健康、状态、版本、跨会话累计、运行投影或渐进展开时，同步检查 [统一触发治理与跨会话信号设计](cross-session-signal-map.md)。
- 实例软件、Skill、模型、独立功能或正式学习变化时，按需读取 `core/protocols/INSTANCE_EVOLUTION_COMPATIBILITY.md`：原生资产与专业扩展复用现有所有者，只有独立组件进入小注册表；不得直接修改母版核心、把本机路径放入便携层，或为兼容登记增加第二次用户确认。旧实例只在隔离升级候选中一次性纳管。
- 修改跨会话运行行为时，以 `core/protocols/CROSS_SESSION_SIGNALS.md` 为执行真源，以 `core/schemas/cross-session-signal.schema.md` 为结构真源；设计说明不能代替二者。
- 修改跨宿主接入、能力发现、宿主协作记忆、任务胶囊或回传来源时，以 `HOST_SESSION_RESUME.md` 和 `HOST_INTEGRATION.md` 分别作为轻量恢复与完整接入的执行真源，以 `core/schemas/host-integration.schema.md` 为结构真源，并同步检查安全边界和 `instance/hosts/` 的按需加载约束。
- 修改升级后的运行行为、完成口径或宿主重载时，以 `core/protocols/UPGRADE_SESSION_ACTIVATION.md` 为会话真源。固定检查只覆盖旧会话待激活、新会话闭合、宿主真实重载、单项行为失败局部隔离和无效启动回滚；不能用静态字符串、手工重读或庞大宿主矩阵代替真实行为验收。
- 修改记忆学习、候选匹配、风险分级、候选复核、正式采用、成熟度、证据压缩或宿主执行经验时，以 `core/protocols/ASSET_LIFECYCLE.md` 为执行真源、`core/schemas/asset-frontmatter.schema.md` 为结构真源，并同步检查 [资产学习、能力进化与 SOP 成熟](asset-evolution.md)、验证证据索引、触发注册表、宿主回传和看板快照兼容投影。风险分级只排序候选，不能单独授权正式资产。
- 修改来源约束交付、正式多文件验收、学习证据资格或任务内修正口径时，以 `core/protocols/RESULT_VALIDATION.md` 为执行真源，并同步检查 [任务结果验证说明](result-validation.md)、资产生命周期、任务交接 SOP、组件变更协议、触发注册表和升级清单。不要按宿主复制验证规则。
- 讨论确认但尚未实现的内容必须标为“已确认设计”或“待落地”，不能写成当前能力。
- 实现完成后同时更新架构文档的状态对照、对应正式协议、组件地图和必要的升级说明。
- 架构文档解释各部分为什么存在以及如何协作；具体可执行规则仍由 `core/protocols/`、`core/guides/` 和 Schema 拥有，避免出现两个互相漂移的正式真源。
- `core/maps/trigger-registry.toml` 是触发规则盘点真源，但普通启动不读取。新增规则必须先归类并声明检查点、状态、投影、门禁、清理与失败行为；不能逐条扩写启动入口。
- 唤醒胶囊和非启动时间索引都是可重建投影，不得成为正式资产真源、无限事件日志或普通任务必读的第四层。
- 宿主注册表和档案属于按需实例元数据，不得加入普通启动扫描；任何宿主专用适配只能引用它们，不能反过来拥有可携带资产语义。
- 当前执行模型、额外接收方、秘密凭据和 GitHub 私有仓库脱敏备份的正式边界由 `EXTERNAL_CONTENT_SAFETY_BOUNDARY.md`、`HOST_INTEGRATION.md` 与 `PRIVACY_IMPORT_EXPORT_SOP.md` 共同投影。修改任一处时同步检查实例清单隐私模式、手动接入提示词、`.gitignore`、看板三项备份／导出／导入动作和公开发布 SOP。
- 修改私密资料登记、`private_refs`、导入导出、分卷或完整换机时，以 `private-asset-catalog.schema.md`、Migration Kit Schema 与隐私迁移 SOP 为共同真源；同步检查目录／当前设备绑定分离、普通启动不加载、旧套件兼容、看板动作、升级保留、README 和公开候选排除。若修改 `core/tools/private_data_migration.py`，还要使用领域无关的合成策略验证不同绝对根、旧根不存在、外部输入重绑、损坏输入保留、流式摘要、事务回滚与第二次零变化；工具的有限单包结果不得代替 Schema 2.0 多分卷覆盖证明。
- `.gitignore` 只能阻止尚未跟踪且命中路径规则的文件，不能发现普通 Markdown／TOML／源码中的误粘密钥，也不能自动移除已经跟踪的秘密。任何 Git 候选副本都必须对准确候选集合做路径与内容检查；报告只显示脱敏类别和位置，不回显秘密原值。
- `.gitignore` 中对本地 Agent／Skill 工具目录的排除只说明它们不属于产品候选，不能代替允许集合。生成公开候选或 GitHub 私有仓库脱敏备份候选时，仍从正式组件清单重建允许集合，不能把某个维护者环境的 Skill、插件缓存或锁文件当作终端用户依赖。
- 根 `.gitattributes` 固定公开源码的文本检出换行为 LF，并把随包字体等格式标记为二进制。修改构建输入、生成器或分发文件时，要在新鲜公开 Git 工作树中重建并确认工作树仍干净；不能把 Windows 的 CRLF 噪声误记成产品变化，也不能用仅比较规范化文本替代原始字节检查。
- 能力与 SOP 正文拥有可携带语义；宿主执行经验只能按稳定 ID 指向核心并在相关任务使用时加载，不能复制或覆盖核心。
- 不把个人实例数据、临时任务包、本地验收记录或维护者私密流程写入公开架构文档。

## 验证强度

个人项目采用风险对应验证，而非默认企业级回归：

- 文案和链接：目标存在、语义一致。
- TOML/Schema：可解析、必填字段和关键约束。
- 安装：在隔离副本中验证完整包识别、冲突分支、桌面入口目标、离线打开和未授权动作清单；不要求普通用户运行开发依赖或全量回归。
- 看板：离线打开、快照错误降级和关键动作复制文本。改到相关模块时验证一条正常旅程和一个最可能的局部失败：可推导漂移修复后继续，无法修复时只暂停相关能力并自然语言说明；严格维护仍可拒绝坏真源。性能或动效只有实际改到对应区域时才做针对性检查，不把每次修改都扩展成完整浏览器矩阵。
- 许可证：根 `LICENSE` 为完整 Apache License 2.0，产品、核心、发布清单和看板包元数据使用同一 SPDX 标识；第三方声明、改写源码映射、字体来源和随包许可证仍完整。普通开发运行 `npm run build`；准备公开候选时再运行 `npm run check:release`，其中包含许可证与合规检查。
- 升级/隐私/安全：针对高风险路径做少量真实场景。
- 隔离副本运行时：用一个合成绑定回指源实例的反例证明当前组件在工具启动前被局部暂停、源缓存零变化，再把同一绑定重连到候选私有运行时并通过；不读取真实实例正文，不扩展成全机扫描或外部软件矩阵。
- 首次实例化：从一份全新模板在隔离目录跑通一个代表性领域实例，核对三文件核心真源、启动可用、0 正式资产、相同输入二次幂等，以及核心提交前回滚和提交后看板故障局部降级。通用与其他领域只有真实逻辑分支变化时再加针对性样例；不要维护多份物理模板，也不要用静态文案检查代替真实创建。
- 私密资产迁移：用完全虚构的小文件、普通归档资料、多集合、大文件分卷和超大单文件分块验证覆盖闭包、导出期间源变化检测、跨卷唯一所有权、全局块表、便携路径／Glob、审批引用降级、部分导出缺项、摘要回读、缺卷／链接／穿越／秘密失败关闭、完整 Schema 1.0 五文件兼容与目标设备不复用旧绝对路径；不读取真实用户资料。
- 旧实例迁移：对实时引用、路径所有权和目录说明冲突做故障注入；先逐字节迁移并回读用户正文，再允许替换模板说明。目标模板只从固定发布内容或可信提交允许集合组装，不能递归带入 `node_modules`、Git 元数据、缓存或非产品维护材料。
- 实例资产：用地图和 frontmatter 做确定性可达性闭包，证明正式 `active`／`provisional`／`review` 资产都有类型一致的直接路线，任务族保持 `on-demand` 且不计资产；不把全库正文交给模型。
- 来源／契约约束结果：用新的阅读轮次比较原始依据与最终产物；同时做必要的解析、稳定 ID、引用、计数、投影和允许范围检查。只有 `validated` 可计学习成功；`limited` 必须暴露边界。

模型可以 3～5 次有根据地自我修正，其中结果验证默认占 1～2 轮聚焦修正；不能为了“通过测试”改掉被冻结的产品语义，也不能把同一事件内的修正重复计为成功证据。

必要检查由 Agent 在变更任务中安静完成。普通用户不需要操作终端、理解测试框架或手工跑回归；这不代表维护者可以跳过与风险直接相关的解析、引用、数据保留、回滚、幂等和真实入口验证。
