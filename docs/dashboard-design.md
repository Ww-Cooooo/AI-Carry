# 看板设计与前端架构

## 1. 看板负责什么

AI Carry 看板是本地、离线、只读的产品界面。它帮助不熟悉代码的用户回答五个问题：

1. 现在有哪些待办，应该从哪里开始；
2. 哪些记忆、流程、能力和经验能跟着自己迁移；
3. 助手正在怎样学习，是否有待办或长期改进计划；
4. 换 Agent、换模型或换电脑时该走哪条迁移通道；
5. 当前模型是否合适、Level 1／2／3 分别什么时候用，以及看板数据和按需读取是否正常。

看板不是真源，不直接改记忆、SOP、能力、治理卡或 Git。需要执行的按钮只复制一份完整自然语言请求，由用户交给当前 Agent；Agent 再通过稳定 `action_id`、地图和协议定位正式流程。这让看板保持跨系统、跨宿主和离线可用，也避免把文件写入能力隐藏在网页事件里。

## 2. 设计方向：Portable Orbit

首页的行星代表 AI Carry，外部镂空蓝色框架代表可以持续增加内容的助手核心，周围卫星分别通向记忆、固定流程（SOP）、能力、待办、经验、长期改进、学习建议和当前模型。用户不用理解文件结构，也能从这些入口找到已经保存的内容。

首屏使用一块完整的产品舞台，而不是把内容挤在页面上方再留下大块无意义空白：左侧在三秒内说清“记得住、用得上、带得走”并给出唯一主操作，右侧放大可交互核心，底部分类坞作为同一舞台的导航底座。舞台随 1024px 以上电脑窗口的高度和宽度伸展；大屏增加视觉呼吸和核心尺度，窄屏优先保住价值、主操作与可读导航，不靠堆卡片填满空间。

这个视觉只承担品牌识别和导航，不承担统计图表。页面其他区域保持浅色、安静、清楚，让视觉重点只有一个：

- 背景使用低对比云白与冷灰蓝，不使用大面积深色；
- 主色只使用 Carry Blue，卫星颜色只用于分类和少量状态提示；
- 阴影短而轻，避免脏雾、过度玻璃感和廉价发光；
- 三维核心有缓慢呼吸、转动和指针视差，卫星有克制的轨道运动；
- 用户要求减少动画时，关闭非必要移动与页面过渡；
- 不把所有卡片做成同一种“模板化大圆角”，通过切角、边界和留白建立层级。

## 3. 信息架构

当前共享网页／客户端的“我的积累”默认展示关系总览，列表作为并列第二个视图保留。总览保留当前有效快照中的全部积累、记录及真实连线，由 G6 力导向布局安排位置，不按类型排成表格，也不按分类抽取代表项。默认查看全图；不同图标和颜色区分内容，名称按可用空间显示，放大或悬停可看清。搜索、类型定位和点节点都先打开侧栏，相关任务记录优先；没有记录就明确说明，不编造任务。用户点“围绕它看关联”后才进入已选定的局部关系网，关联多时按组展开。绿色实线表示来源或形成，蓝色虚线表示在任务中使用；距离不代表关系强度，动效也不表示任务正在执行或已成功。轻漂浮可暂停，并遵守减少动效、隐藏及离开页面状态。“跳转到列表”定位并展开对应条目，原复制请求不变；“全部积累”仍放在列表分类末尾，未选时用浅灰绿，选中才用蓝色。连线绘制失败保留可点击条目、详情和列表，不影响其他功能。

两项或更多积累以同一内容为来源时，该节点显示绿色分支标记与“共同来源”标签，也可从同名入口找到。只依据已有来源、学习或整理关系计算不同的目标积累，不把使用次数、节点大小或画面中心当作来源证据。允许多个共同来源，不推断唯一源头。点选仍先开侧栏；来源、以它为来源的积累和使用记录分开说明，探索中心明确标为“当前查看”。

普通点选先展开详情，再围绕目标连续放大、移动，保留同一关系网，不重排节点。侧栏改变画布宽度时保持原有视野位置；已达到可读尺度时不反复放大。新点选取代旧定位，关闭详情或手动拖动、缩放可以取消自动靠近；减少动效模式直接到达可读位置。只有“围绕它看关联”才切换局部网络。

关系取自现有正式来源，不根据相似标题推断。来源记录与真实使用记录分开，快照用匿名编号展示任务和来源记录，不展示原始对话或私密路径；这不代表原资料没有名称。关系只是按需展示，不加入普通启动上下文。G6 与现有脚本一起本地打包，进入地图时才创建画布，网页 `file://` 与 Electron 共用实现，不依赖远程运行资源。

旧结构按内部资产类型逐层展开，用户首先看到的是系统分类和统计图。新版按用户意图组织为六个入口：

| 入口 | 用户问题 | 主要内容 |
| --- | --- | --- |
| 总览 | 我现在应该做什么 | 自然语言开场、助手核心、第一次设置或下一待办、资产概览、最近变化 |
| 随身资产 | 有什么会跟着我走 | 记忆、固定流程（SOP）、能力、经验；记忆页从正式记忆中单独分组显示“我的习惯”，支持查看适用范围、纠正和停止沿用；其余内容支持分类、搜索、详情和复制调用请求；页面先用紧凑小流程概括形成或使用路线，点击后再打开完整验证／复核或经验说明 |
| Skill 工坊 | 哪些好方法适合整理，别人的 Skill 怎样安全接入 | “我的方法 → 可分享 Skill”和“别人的 Skill → 我的助手”两条装订轨；推荐不触发转换，用户指定方法后由 Agent 复制该方法并只在本地草稿中自动脱敏、通用化，原方法不变；共享 Skill 只读检查且不静默改写，说明影响并得到确认后才安装；本地草稿与已安装 Skill 只显示低敏摘要 |
| 待办与成长 | 还有什么要做，助手如何变好 | 普通待办、学习建议、长期改进；三者不混为一种任务 |
| 迁移与安全 | 怎样登记要带走的资料、换 Agent、换电脑或做远程脱敏备份 | 独立区分同机换本地 Agent 与整套换机迁移；先说明登记范围与覆盖保证，再提供主体包／私密分卷迁移、GitHub 私有仓库脱敏备份、单独导出／导入和安全提醒 |
| 当前状态 | 现在是否正常、该用哪个等级 | 看板数据、当前模型、Level 1／2／3 用途、随身内容、按需读取、实例身份与维护者信息 |

首页有八个卫星入口：七个内容组（记忆、固定流程、能力、待办、经验、长期改进、学习建议）加一个当前模型状态。当前模型只是运行状态，不属于可携带资产。卫星和分类坞只做深链接，不预读正文，也不把这些内容一次塞进模型上下文。

所有入口采用同一套三级信息密度：默认层只回答“是什么、现在怎样、能做什么”；点击层只保留完成当前操作需要的核心详情；术语含义、判断依据、边界和少见例外放进可悬停、可聚焦、可点击的问号提示或低优先级展开区。关键错误、风险、主要操作和真实下一步必须直接可见，不能藏进提示层。三级展示复用同一份正式内容，不建立第二套摘要真源。

模板首页仍只保留一个“创建我的助手”首要操作。点击后使用三步弹窗承载必要选择，而不是在首页铺开六张组合卡：第一步选择可调整的交流方式，第二步选择通用／专业方向或“先帮我判断”，第三步核对并生成完整 Agent 请求。选择卡默认只显示名称和一句结果，适用人群、差异和锁定原因通过问号解释；最终核对只直接显示两项选择、修改入口、正式预览确认和主操作。用户点击“生成创建指令”后，要把完整内容交回当前 Agent／聊天；复制成功时直接露出几行真实指令，以渐变和省略号提示后续内容，并允许展开全文；复制失败时必须直接显示全文供手动复制。这个按钮只组织自然语言请求，不直接写入清单，也不等于实例化已经完成。弹窗选择只存在于当前页面内，关闭或刷新可以丢弃。正式实例的“当前状态”显示当前交流方式，并可生成只调整 `profile.guidance_mode` 的请求；方向没有修改入口。成功安装空白模板后，安装 Agent 应在宿主支持时把看板呈现在用户可见窗口中，并用总览首屏的“创建我的助手”主按钮作为稳定语义锚点说明入口；同时必须在聊天中提供完整备用路线，不能把是否会找按钮当作用户继续设置的前提。

正式实例还要在左侧固定身份卡和总览开头显示当前 `profile.display_name`，不论用户进入哪个栏目都能辨认助手。产品 Logo 继续表示 AI Carry，不承担实例身份；模板显示“尚未创建助手”。长名称允许两行并在悬停时显示完整值，不能为了塞进一行把字号缩到难以阅读。

## 4. 文案原则

看板默认面对不懂编程的用户，因此先说“用户要完成什么”，再说内部术语：

- 使用“创建我的助手”“带到另一台电脑”“看看随身资产”等动作与对象完整的标签；
- “一步步引导／适度引导／直接协作”只描述交流方式，不写成用户等级；三者都能创建通用或专业助手，避免默认用户是小白或程序员；
- 第一次出现 SOP 时写作“固定流程（SOP）”；
- 不把内部机制名、数据结构名或路由术语直接交给普通用户；需要保留的 Level、SOP、GitHub 等名称必须紧邻解释；
- 固定流程和能力在普通界面只显示“待验证、需要复核、可使用”。详细成熟度与验证证据继续保存在正式资产中；
- 问号只补充术语、判断依据、边界或少见例外。用户该去哪里验证或复核、当前发生了什么和下一步做什么必须直接显示，不能藏进悬停提示；
- 学习建议列表先显示标题、简要用途、状态和操作；点击后显示建议去向与下一步，来源、观察授权和记录信息再按需展开。来源只显示低敏自然语言摘要，不展示事件 ID、路径、日志、隐私或外部攻击载荷；建议去向不等于已经生成正式资产；
- 记忆页必须解释用户不需要准确说出资产名称：日常语言先匹配极小地图，命中后才读取正文。`subtype=habit` 的正式记忆集中显示为“我的习惯”，卡片先显示标题、用途和状态；点击后再显示适用范围，并提供“纠正”和“停止沿用”的自然语言操作，来源说明放入按需层。后者仍由 Agent 预览影响并按风险确认，不由网页直接删除文件；
- 看板要让用户看见主动学习闭环：“真实任务中发现 → Agent 用普通话询问 → 用户确认内容与范围 → 以后按任务自动使用”。这条说明依附在记忆与习惯的既有页面中，不新增装饰性控制台或虚构数据；模板没有习惯时显示真实空态，在线演示只使用私密维护层提供的纯虚构习惯。
- 形成、验证和经验说明不能长期占据整页。页面先显示能一眼读完的四步路线；用户点击后，弹窗只展开核心关系，单步依据和示例继续由问号按需解释。紧凑展示只减少视觉负担，不能删掉来源、证据、边界或失败处理；
- 固定流程和能力页面必须把正式成熟路线翻译成可视顺序：首次使用前为待验证；第 1 次独立成功后可使用；第 2 次继续积累但不机械升级；通常至少 3 次独立成功、2 种任务情境、范围稳定且无未解决重要失败后才记为可靠；达到可靠后再经过真实跨宿主或实质环境变化验证。任务内重试只算一次，高风险资产可以要求更多证据；
- 首次使用之前必须先解释资产来源：真实任务或用户要求产生学习信号，Agent 先形成有来源、有范围的候选，再判断它属于能力、固定流程还是经验；获得保存授权不等于已经验证，没有成功证据时仍为“待验证”；
- 失败、环境／版本／权限变化或证据冲突会让任何阶段进入“需要复核”。页面要直接画出检查旧证据与当前环境、在下一项合适真实任务中重新验证、按结果恢复或继续复核的路线；
- 经验页面要清楚解释它是一次真实任务的复盘记录，包含背景、成败、修正、证据和边界；它不同于长期事实／偏好的记忆、说明会做什么的能力和规定复用步骤的固定流程，也不会在新任务中被原样照搬。详细弹窗还要说明：只在当前任务与某条经验真正相似时打开卡片、复制参考指令、交给当前 Agent 按需读取，并先比较当前条件再采用；
- 模板空态解释下一步，不展示维护者的示例身份、具体日期或演示资产；
- 没有待办、学习建议或长期改进项时保持安静，不为了显得活跃而制造数据；
- 技术字段收进“给维护者看的技术信息”，不占据日常首屏；
- 复制请求必须包含目标、稳定 ID、路由、范围、禁止事项、确认点和完成回报，不能只复制一句含糊口令。

## 5. 数据与动作边界

```text
正式 Markdown / TOML 资产
          ↓ 由 Agent 按 Schema 生成
本地 snapshot.js（可删除、可重建的只读投影）
          ↓ 前端读取并展示
看板卡片与状态
          ↓ 用户点击
完整自然语言请求 → 当前 Agent → 地图 / 协议 → 正式操作
```

数据契约由 `core/schemas/dashboard-snapshot.schema.md` 拥有。全局动作的正式登记表是 `core/maps/dashboard-actions.toml`，字段与执行边界分别由 `core/schemas/dashboard-action.schema.md` 和 `core/protocols/DASHBOARD_ACTIONS.md` 约束。`dashboard/src/lib/data.ts` 保存供离线产物使用的编译镜像，必须通过验收与正式登记表保持一致；动作新增或修改后要重新构建看板。快照只携带展示数据，任何 `actions` 字段都会被前端忽略，不能覆盖或凭空创建按钮请求。前端不得：

- 直接扫描整个资产库；
- 把快照反向写回正式资产；
- 用演示文案替代快照中缺失的真实说明；
- 把页面自己的 60 秒读取倒计时当作长期治理调度器；
- 在 GitHub 私有仓库脱敏备份的本地检查和仓库预览完成前创建仓库、提交或推送，或自动改为公开仓库、添加协作者；
- 把 API 密钥、密码、令牌、Cookie、私钥、恢复码或登录态放进快照、复制请求或模型上下文。

Skill 工坊不改变这条边界。推荐由当前快照中的正式状态、授权和成熟度即时计算，只供用户选择；它不接受脱敏处理、不触发转换、不回写资产，也不制造待办。用户明确指定一个方法并把整理请求交给 Agent 后，Agent 才复制该方法，并只在这份隔离草稿中自动完成隐私检查、脱敏、通用化和参数化；用户不用先手工处理，推荐列表和来源资产保持不变，生成本地草稿也不表示已经分享。共享 Skill 走另一条路线：按钮明确只复制起始请求，用户发给 Agent 后，若尚无唯一来源，Agent 引导其提供本地文件夹、ZIP 或链接，再进行只读检查；不为通过检查而自动脱敏或静默改写，说明影响并得到确认后才安装。`skills.items` 只显示标题、用途、触发、平台和状态；`skills.exports` 只显示本地导出的标题、用途和状态。每条已生成 Skill 可打开低敏详情，只解释用途、当前状态、分享边界和下一步；入口、来源地址、本机路径、来源资产 ID 与正文永不投影。详情页恰好提供一个与当前状态相符的“交给 Agent”动作：草稿继续检查、就绪项准备分享预览、复核项先解释问题；按钮只复制带稳定 ID 的受控请求，网页不直接检查、修改、上传、发送或发布，复制也不构成外部分享授权。状态颜色只作辅助：“可以分享”“本地草稿”“需要复核”和方法成熟度都必须带可访问的问号说明，回答状态含义、常见原因和下一步。工坊按钮只复制 `skill.create-from-asset`、`skill.continue-export` 或 `skill.install-shared` 完整请求，网页不转换、不下载、不执行脚本、不安装。

创建助手向导必须维持只读边界：网页可以把用户刚刚选择的交流方式和方向意向附加到受控 `instance.instantiate` 请求，但不能写 `instance/manifest.toml`。“先帮我判断”只能让 Agent 了解情况和提供比较，在用户明确选择 `general` 或 `domain` 前不得锁定。调整交流方式使用独立的 `profile.adjust-guidance-mode` 动作，只允许更新 `profile.guidance_mode` 和重建快照；不得重做实例化、改变 `direction` 或改写长期资产。

右上角状态不能只是颜色提示，也不能与“当前状态”页各自判断。两处必须共用同一状态函数，至少区分：正常本地同步、模板未设置、快照不可用、更新时间缺失／异常、数据超过有效范围、本机时间不一致和重新读取失败。状态入口使用可聚焦按钮打开有焦点管理的说明弹窗，直接回答“这是什么意思、为什么出现、现在怎么处理”；正常状态明确它不是 GitHub／云同步，异常状态优先提供本地重新读取，持续异常时再复制 `dashboard.refresh-snapshot` 修复请求。颜色只作辅助，文字、图标和操作必须独立表达含义。

迁移页必须先让用户选择去向，不能再用一个含糊按钮同时代表换 Agent 和换电脑：

- `host.prepare-agent-switch` 只用于同一台电脑上的另一个本地 Agent。能读取当前目录时，新 Agent 接入同一份可携带主本；只能交换文字时生成当前接入和任务所需的有界胶囊。它不得打包或重复复制整套资产；
- `instance.review-private-coverage` 用于登记或核对要随助手携带的外部资料，不扫描整台电脑；界面必须明确“完整保证只覆盖已登记和已引用范围”；
- `instance.prepare-complete-migration` 用于另一台电脑。它按 Migration Kit Schema 2.0 生成主体包、一个或多个私密分卷、固定入口、顶层清单和校验文件。小型实例仍是五文件体验；大型资料自动分卷，用户仍只搬一个文件夹。三步引导的说明页只展示三项摘要，选择页只展示选项结果，核对页只展示所选方式与三步标题；适用情形、判断原因和边界细节放进问号。界面不能暗示旧电脑绝对路径会被保留，也不能把 GitHub 备份说成迁移前提；
- 两个入口都只复制完整请求。看板不会自行打包、外发、上传、删除源实例或宣称宿主中尚未导入 AI Carry 的记忆已经迁移。

记忆页要同时消除三个误解：用户不需要先点卡片才能让记忆生效，不需要记住准确资产名，也不应以为全部记忆会在启动时进入上下文。页面固定解释“用日常语言说出任务 → 极小目录判断相关性 → 必要时确认少量候选 → 只读取命中的正文”；卡片上的手动操作必须标为可选补充。习惯仍是记忆子类，显示分组不能改变资产总数。记忆列表和详情在形状、信息结构和动作配色上与流程／能力区分，但仍复用同一设计系统。

普通正式状态变化先写入并回读自己的真源，再尽力重建快照：快照先生成临时文件，校验后原子替换 `snapshot.js`；刷新失败只让看板显示待更新，不撤销已成功的真实变化。恢复、升级和正式发布在宣布完成前仍须闭合最终快照。页面每 60 秒或用户点击“重新读取本地快照”时，只用带时间戳的查询参数重新读取这个小文件；没有变化就不重绘，发生变化时保留当前栏目、滚动位置与 Three.js 实例。页面没有扫描正式资产的权限，因此只能依据 `generated_at` 与 `freshness_seconds` 给出保守的过期提示，不能自行证明来源文件已经变化。需要核对来源摘要或真正重建时，用户复制 `dashboard.refresh-snapshot` 请求交给 Agent。

浏览器入口必须同时帮助用户辨认“这是模板、哪一个实例，还是在线演示”。根 `dashboard.html` 在跳转到正式离线产物时，把快照中的类别、匿名 `identity_ref` 和产品版本写入 `ac_kind`、`ac_ref`、`ac_version`；React 页面再与实际快照交叉核对。浏览器标签显示可读名称，地址只带匿名编号，不得放实例名、方向、路径、个人资料或秘密。没有入口胶囊时可以从当前快照补齐；模板变成实例和同一实例升级版本是允许自动更新的正常变化。已经建立身份的实例入口加载了另一份实例、模板或演示时，不得静默改写入口：页面保留只读浏览和重新读取，醒目提示错入口，并阻止所有会把请求交给 Agent 的复制动作。该胶囊只用于发现误开，不承担认证或授权。

### 5.1 在线演示不是安装内容

项目 README 可以链接到公开仓库的 GitHub Pages 演示。它不是第二套看板：页面必须直接复用当前正式构建的 `dist/index.html`、本地字体、许可证和交互代码，只把 `snapshot.js` 替换成经过检查的纯虚构快照。页面顶部必须持续显示“在线演示、纯虚构数据、正式安装从空模板开始”，不能让访问者把示例身份、日期、待办或资产当成自己的内容。

公开 `main`、源码压缩包、Release 安装包和本地安装目录不得包含演示快照或测试夹具；公开 `gh-pages` 分支只保存可直接托管的静态演示产物。在线演示必须复用正式界面代码，不能维护第二套组件，也不能让演示数据回流到安装包。README 中的在线链接只有在远程页面实际可访问后才算可用。

在线演示的按钮仍只是页面交互与复制请求，不会修改访问者设备。Pages 不收集用户资料、不处理秘密、不承担登录、交易或 SaaS 后端功能。普通用户、公开贡献者和公开模板都不需要操作远程 Pages 发布。

### 5.2 中文默认与英文用户层

看板只维护一套 React 组件、动作镜像和离线构建。根 `dashboard.html` 默认进入简体中文；英文安装入口 `dashboard.en.html` 添加 `ac_lang=en` 提示后进入同一份 `dist/index.html`。顶部语言按钮是真实用户控制，选择在当前本地看板可存储时被记住，并优先于入口提示。页面同步更新 HTML `lang`、浏览器标题、导航、状态、日期、无障碍标签和复制请求，不按 IP 或地区选择语言，也不请求在线翻译服务。

受控词库只包含经过审核的产品文案。未登记字符串保持原样，因此用户自己的记忆、能力、SOP、经验、专业资料和本地隐私内容不会被界面自动翻译。英文复制动作先添加“全程用英文与用户交流”的宿主约束，再携带中文正式动作请求；正式路由、安全、迁移、确认和验收只维护一份真源。Pages 使用单独的纯虚构英文快照和同一正式界面代码，不把中文演示资料运行时翻译成用户数据，也不进入公开 `main` 或安装包。

## 6. 前端组成

| 层 | 选择 | 作用 |
| --- | --- | --- |
| 应用 | React 19 + TypeScript | 状态、路由、视图组合和可维护组件边界 |
| 构建 | Vite 8 | 开发体验与生产打包；最终通过适配脚本生成可由 `file://` 打开的离线页面 |
| 三维 | Three.js | 首页行星、镂空框架、卫星、轨道、光照与指针视差 |
| 动效 | Motion + CSS 合成层 | Motion 负责页面切换和进入视口动画；不接收点击的 CSS 合成层负责首页首要操作的低强度呼吸反馈，两者都服从系统减少动画偏好 |
| 关系图 | React Flow | 用真实协议解释待办、学习建议与长期改进的流转；不提供无意义拖拽、缩放或控制面板 |
| 长页滚动 | Lenis | 只增强桌面主内容的滚轮连续性；触屏、减少动态、页面隐藏或不适用环境自动退回原生滚动 |
| 交互基础 | Radix UI | 对话框等需要键盘、焦点和 ARIA 语义的基础组件 |
| 组件模板 | shadcn/ui（改写源码） | 按钮、徽章、对话框和 Tailwind v4 主题脚手架；保留 MIT 来源映射与修改说明 |
| 样式 | Tailwind CSS 构建能力 + 项目设计令牌 | 生成基础能力；主要视觉由项目自己的语义类和设计令牌控制 |
| 图标 | Lucide | 一致、可访问的开源线性图标 |

这些直接运行依赖采用允许开源分发的许可证；准确版本以 `dashboard/package.json` 和锁文件为准。React、Three.js、Motion、React Flow、Lenis、Radix UI 与 Tailwind CSS 使用 MIT 许可，Lucide React 使用 ISC，`class-variance-authority` 使用 Apache-2.0。React Flow 的生产依赖中包含 BSD-3-Clause 的 `d3-ease`，完整文本随生产依赖清单分发。shadcn/ui 模板不是 npm 依赖，而是已修改并保存在仓库中的 MIT 源码，因此由单独的来源清单覆盖。看板把应用代码和框架编译进离线 `index.html`，不在用户打开时读取 npm、CDN 或远端脚本。

字体采用三个清楚分工且全部可随包分发的 OFL 1.1 家族：Noto Sans SC 负责中文正文、常规英文与数字；Space Grotesk 负责品牌标题和展示数字；Noto Sans Mono CJK SC 的 Regular／Bold 负责代码、路径、ID 与中英技术文本。完整字符集转成 WOFF2 后随仓库分发，不依赖微软雅黑、苹方等平台字体，也不做可能让姓名或专业术语缺字的常用汉字裁剪。

字号不是由各组件随意决定，而是由 `index.css` 中的语义层级统一控制：12px 只供版本号、数量、时间和状态等短元数据使用；13px 用于辅助说明；14px 用于标签与卡片正文；15px 用于主要控件；16px 是常规正文基线；17px 用于需要更强阅读连续性的正文；26px 是常规分区标题。首页与页面主标题在 32–46px 之间随可用宽度平滑变化。正文采用约 1.6–1.72 的行高，标题采用更紧凑的行高。放大字号时允许同步增加导航宽度、控件高度与窄窗口图例行数，不能用截断、重叠或缩回小字来维持旧布局。

AI Carry 自身采用根目录 `LICENSE` 中的 Apache License 2.0；根目录的 `THIRD_PARTY_NOTICES.md` 单独说明依赖、改写源码与字体。`dashboard/public/licenses/` 保存字体原始 OFL、shadcn/ui 来源映射与 MIT 文本，以及当前锁文件中全部非 dev 依赖的机器清单和许可证全文，并在构建时原样复制到 `dashboard/dist/licenses/`。`font-manifest.json` 固定字体版本、版权、Reserved Font Name 审核、上游提交、源文件与产物 SHA-256 及转换验证。构建会拒绝过期许可证清单、未审核依赖许可、未登记二进制素材、缺失字体、校验和不符或远端运行资源。完整规则见 [开源合规与第三方来源](open-source-compliance.md)。

## 7. 为什么只加入有明确职责的框架

技术选择以产品适配为准，不以依赖数量为目标：

- 没有迁移到 Astro。Astro 的内容驱动、服务端优先模型很适合文档站和内容站；当前看板是一个本地、状态化、以交互为主的 React 应用，迁移不会改善核心体验，反而会增加双重运行模型和离线构建复杂度。
- Lenis 只接管电脑端主内容滚轮，并在触屏、减少动态或页面隐藏时自动停用；它不接管对话框或键盘焦点，也不在页面上制造控制器。
- 重复卡片列表继续保留正常 DOM、浏览器查找和辅助技术语义，但用浏览器原生 `content-visibility: auto` 跳过屏外卡片的布局与绘制；`contain-intrinsic-size: auto ...` 按内容盒和 1024px 电脑窄窗预留高度，避免卡片出现时滚动条跳动。进入动效以真正滚动的 `.app-main` 为观察根：卡片进入可视区后才用一次性的透明度、向上位移和极轻缩放逐张呈现，左右卡片只做短错峰；不能在屏幕下方数百像素处提前完成，也不能被路由容器的首次动画设置取消。迁移页这类包含多种网格、说明和操作的异形大区块不整块延迟，避免把一次性布局成本推迟到滚动途中。当前每类只有少量、尺寸不一的卡片，因此不引入面向超长同构列表的虚拟化框架；只有真实数据规模证明有需要时才重新评估。
- 平滑滚动只允许一个所有者：当前是 Lenis。HTML 与主滚动容器不再叠加 CSS 平滑滚动，也不再安装第二套滚动增强。主容器产生统一滚动状态，供 Three.js 自动让帧；它不是业务信号、不会写入快照或启动上下文。
- 首页 Three.js 在静止时最高约 60 帧／秒，主内容滚动时保持约 30 帧／秒；所有旋转与呼吸按真实时间差推进。页面隐藏、核心离开视口或减少动态时停止连续循环，指针与尺寸变化仍可请求一帧。首要按钮继续保留低强度呼吸光晕与掠光：可点击按钮及其命中区域保持固定，外层阴影固定绘制，只有不接收指针事件的独立光晕层改变透明度和缩放，不再逐帧插值阴影；既不能为了性能删掉用户可见的情绪反馈，也不能让动画妨碍点击或持续抢夺注意力。
- React Flow 只承载原本就需要解释的三类真实流程。节点文字来自正式协议，页面不允许为了证明用了图表库而制造指标、示例资产或可拖动的“演示工作台”。
- 没有加入后处理 Bloom。首页已经用几何、材质与局部光照实现轻微闪亮；全屏 Bloom 会重新带来用户明确不喜欢的脏雾和强光晕，并增加 GPU 成本。
- 没有使用 React Three Fiber 重写已经稳定的 Three.js 场景。它是成熟的 MIT 开源方案，但当前直接 Three.js 的资源释放、动画循环和交互边界清晰，重写没有用户价值。

后续只有在出现明确需求和可验证收益时才增加这些能力。

## 8. 离线、电脑窗口适配与可访问性

- 根入口 `dashboard.html` 读取同目录的极小快照身份后跳转到 `dashboard/dist/index.html`，并把模板／实例／演示类别、匿名引用和版本放进地址；最终用户不需要终端、本地服务或网络。
- 英文安装创建的入口指向 `dashboard.en.html`，它只增加英文语言提示并复用相同快照身份与正式离线产物；用户切回中文后，本地选择优先，不能被入口每次强行覆盖。
- Agent 引导安装必须在桌面或系统等价的明显位置创建“AI Carry 看板”入口，并让它指向正式安装目录中的根 `dashboard.html`。不能把根网页单独复制到桌面；快捷方式可在路径或系统变化后重建，不属于正式资产真源。Windows 验收必须使用当前 Shell／Explorer 认可的已知桌面位置，不能拼接用户主目录；入口还要经系统能力回读目标和工作目录，并从入口实际观察到看板主要界面，单纯“命令返回成功”不算完整通过。
- 构建产物把应用脚本与样式内联；四个字体面（正文可变字重、展示可变字重、代码 Regular／Bold）、`snapshot.js` 和许可证包保持本地同级资源，不访问 CDN，也不依赖用户操作系统是否安装某种中文字体。
- 当前验收基线是在 Windows 的现行 Edge／Chromium 内核中通过 `file://` 运行；现行 Firefox 与 Safari 是兼容目标，但在完成对应平台实测前不能写成“已验证”。
- 不注册 Service Worker；自动与手动重新读取都会给 `snapshot.js` 附加时间戳查询参数，避免浏览器缓存把旧快照误当成新状态。
- 看板只承诺电脑端使用，正式目标宽度为 1024px 及以上。低于该宽度的紧凑导航和文字流程只用于电脑窗口临时缩窄时防止界面崩坏，不构成手机或平板支持承诺。
- 可见界面文字不得小于 12px，且 12px 只能用于低优先级短元数据；说明与连续阅读文本通常应为 13–17px。不能为了塞进窄窗口而把文字压回 8–11px。
- 主要按钮至少提供 44px 左右的触控空间；图标按钮有可读标签或 `aria-label`。
- 分类使用真正的 Tab 语义，页面入口使用 `aria-current`，弹窗由 Radix 管理焦点，页面提供跳到主要内容的链接。
- 所有文本必须允许合理换行；真实资产标题和说明不能依赖演示长度。
- 监听 `prefers-reduced-motion`：关闭非必要进入动画、平滑滚动和星体连续运动；静态信息与导航仍完整可用。
- 首页“创建我的助手”或“继续第一件事”是每天最先使用的操作。它可以有低强度呼吸与掠光来提示“从这里开始”，但不得跳动、持续抢夺注意力或增加控制按钮；减少动态模式下自动变为静态按钮。
- 页面隐藏或 Three.js 区域离开视口时，连续渲染自动暂停；重新可见时恢复。用户没有暂停、旋转或重置 3D 的实际任务，因此界面不显示这些控制器。
- 长页中的屏外卡片只在接近可视区时参与完整绘制；内容始终保留在 DOM 和无障碍树中。预留高度按支持的电脑宽度校准，不能为了省一次绘制制造滚动条跳变。卡片进入效果必须在真实主滚动容器中可见地发生一次；减少动态时不保留透明占位，所有内容立即可见。Lenis 只增强滚轮，减少动态或不适用环境必须直接回退原生滚动。
- WebGL 初始化失败或运行中上下文丢失时，三维区必须降级为二维行星、轨道／卫星提示和明确说明；下方可访问分类坞仍须可用，不能让首页空白。验收同时覆盖初始化失败与 `webglcontextlost`。

## 9. 扩展规则

新增资产类型或全局动作时，应按下面顺序处理：

1. 先确认它是否属于正式产品语义，而不是某个宿主的临时能力；
2. 更新正式 Schema、地图或协议；全局动作以 `core/maps/dashboard-actions.toml` 为真源；
3. 更新快照生成规则与数据投影；
4. 在 `dashboard-config.tsx` 中加入稳定分类和导航关系；
5. 提供模板空态、真实数据态、字段缺失态和长内容态；
6. 如果按钮会引导真实操作，登记稳定 `action_id` 和完整请求，不在网页里直接执行；
7. 验证离线、常见电脑窗口、键盘、减少动画、无外部请求和控制台无错误；
8. 跟随 `core/maps/component-map.toml` 更新升级清单与公开文档。动作只是修改标签或请求正文时，同步正式登记表与前端兜底；只有动作投影字段或结构变化时才修改快照 Schema。

不应因为增加一个条件触发、治理日期或宿主能力，就把完整规则塞进启动上下文或看板快照。

首页和“当前状态”的“当前可见可携带内容”数字统计七个内容组在快照中的可见条目；隐藏待办仍保存在正式资产中，但不计入这个界面数字。模型、本地扩展、缓存和可重建索引不计入。单独的“随身资产”页面只统计该页管理的记忆、固定流程、能力与经验四组。

## 10. 验收基线

每次看板变更至少检查：

- `npm run build` 成功，`dist/index.html` 能直接通过 `file://` 打开；
- 正式模板显示真实空态，不含维护者身份、演示资产或具体治理日期；
- 使用不提交仓库的临时合成数据检查七个内容组、当前模型状态、长标题、长说明、完成／隐藏待办和缺失说明；模型不得计入可携带资产，合成数据不得进入公开 `main` 或安装包；
- 如果 README 提供在线演示，远程页面必须复用当前正式界面、显示纯虚构演示提示，并在看板变化后重新核对实际页面，不能让旧页面冒充已同步；
- 五个入口、Hash 深链接、浏览器前进后退、搜索、详情与复制请求可用；
- 模板、正式实例和在线演示分别得到正确浏览器标题与 URL 身份胶囊；入口与快照身份冲突时保持可查看、禁用复制指令并给出普通语言修复说明，模板转实例和同实例升级不会误报；
- 安装验收能从桌面或系统等价入口打开根 `dashboard.html` 并进入完整离线看板；入口不能依赖源码目录浏览、终端、本地服务器或 npm；
- GitHub 私有仓库脱敏备份、本地隐私迁移、同机 Agent 接入和整套换机迁移保持边界清楚。GitHub 脱敏备份必须先给出本地检查结果和仓库预览；私密分卷不得上传；同机换 Agent 不复制整套资产；整套换机保持主体包、全部私密分卷和恢复校验说明分离。登记动作不能暗示全盘扫描，完整迁移动作必须要求覆盖对账。复制文本必须包含秘密与额外接收方边界，绝不能把真实凭据复制进去；
- 快照中的任何 `actions` 字段都必须被前端忽略；全局动作只能由正式登记表与同步构建的离线镜像提供；
- 1024×768、1366×768、1440×900 与 1920×1080 等常见电脑窗口没有横向溢出；
- 逐页检查计算后的实际字号：可见 DOM 文本不低于 11px，正文和主要操作保持既定语义层级；导航说明、按钮文字、状态和对话框不得因放大而被意外截断；
- 键盘焦点可见，减少动画模式可用，控制台和页面没有错误；
- 页面没有外部网络资源，也不会因重新读取本地快照而重载整页或重建 Three.js 核心。
- 中文入口默认得到 `zh-Hans`，英文入口默认得到 `en`；英文模式的十个主要分类页面、首次创建与迁移弹窗不残留非目标中文（语言按钮的目标名称“中文”除外），浏览器标题和无障碍标签同步；切换后仍无远程请求。
- 使用一个临时快照注入未登记的用户自定义中文标题，确认英文模式保持原文；产品自带英文文案正常切换，复制请求包含英文宿主说明、中文正式请求和密钥排除边界。
- 在相同浏览器、视口和 CPU 节流条件下比较变更前后滚动采样：首页滚动期间 Three.js 绘制调用应显著下降；长页屏外区块使用原生延迟绘制，逐步出现时没有布局位移、横向溢出、远程请求或控制台错误；减少动态模式不启动 Lenis 和连续三维循环。
- `font-manifest.json` 中四个字体面的文件、SHA-256 与 OFL 1.1 均匹配，生产依赖许可证清单与当前锁文件一致；旧字体不得作为未使用负担残留在分发包。
- `source-code/source-components.json` 中每个改写源码文件、固定上游提交、版权与许可证摘要可核对；任何新增二进制素材都已登记或被门禁拒绝。
