# AI Carry 离线看板

看板是 AI Carry 的本地只读界面。最终用户双击完整安装目录中的 `dashboard.html` 即可离线打开；查看页面不需要终端、本地服务、Node.js 或网络。正式创建、保存和升级由用户选择的 Agent 调用随包工具完成，运行条件见 [安装说明](../INSTALL.md)。

## 页面与实际操作

网页与桌面客户端共用 `src/app/` 和 `dist/`，不是两套产品：

- **总览**：介绍用途，进入首次创建或已有积累。
- **我的积累**：在地图或列表查看记忆、SOP、能力、经验及已有来源关系；没有关系数据时仍可使用列表。
- **Skill 工坊**：从已保存的方法整理 Skill，或检查、接入别人分享的 Skill。
- **待办与成长**：分开显示待办、学习建议和长期改进。
- **迁移与安全**：换 Agent、换电脑、私密资料导入导出、备份、升级和问题报告。

右上角还有助手设置和使用说明。首页的卡片与知识袋用于导航，不是用户资料的真源。

需要执行的操作遵循“预览请求 → 按需补充 → 复制 → 发给 Agent → 在该对话查看结果”。页面不会直接保存正式资产、连接 Agent、启动任务队列或上传资料。自动复制失败或剪贴板未及时返回确认时，完整请求仍可展开、选中并手动复制；这不是在等待 Agent 执行回报。已经发出的请求先在原 Agent 对话核对结果，不因看板没变化重复发送。

首次创建先选使用经验，再选助手方向，最后核对并生成请求。页面中的选择不等于实例已创建，仍需 Agent 展示完整方案并按确认范围执行。

## 数据、刷新与故障

网页版读取 `dist/snapshot.js` 中的 `window.AI_CARRY_SNAPSHOT`，兼容旧版快照名称。它是可重建的显示数据，不是记忆主本。点击“重新读取”只重新加载本地快照，不重建资产或执行任务；当前网页版没有每 60 秒自动轮询。Agent 保存新内容后，可以回页面手动读取。

桌面客户端使用自身受信任的读取器，从选定助手目录的正式来源生成只读投影；不会执行所选目录的快照脚本。窗口重新获得焦点时会尝试刷新。源码入口见 `../desktop/`。

首次创建、学习保存等操作先闭合正式来源，再尽力刷新投影。快照刷新失败不能撤销有效的助手或资产。单项坏记录应局部隔离并说明源资料仍保留，不能把缺失数据显示成已经验证为空。网页刷新失败保留上次内容，并说明没有读到新资料；初次读取失败不冒充正常空模板。

确认进度时，分别看这三项：Agent 是否报告正式内容已写入并回读；是否报告快照已重建或仍待刷新；页面重新读取后，助手、版本及本次条目是否与 Agent 的回报一致。页面没有报错只能证明读到了显示数据，不能证明所有源文件正确。

如果页面无法提供请求，直接告诉 Agent：“请确认这份 AI Carry 的目录和实例身份，保留我的原资料，只检查相关错误并重建看板，不要重新创建助手。完成后说明哪些已恢复、哪些仍待处理。”重建后重新读取并核对本次相关条目。

根入口会添加不含用户语义的 `ac_kind`、`ac_ref`、`ac_version` 地址提示，帮助辨认模板、实例和演示。它不是认证或授权凭证。页面中的实际执行请求仍交给 Agent 核对目标、身份与授权。

同机换 Agent 默认创建独立副本，原目录不动、两份不自动同步；只有明确选择轮流共用时才使用原目录。换电脑使用迁移套件，助手主体与登记的私密资料分开携带，秘密凭据在新环境重新配置。单个包、工具、快照或客户端异常只影响对应部分，不应阻止其他独立工作。

## 开发与验证

前端开发推荐 Node.js 24；当前 Vite 要求 Node.js `^20.19.0 || >=22.12.0`。使用锁文件安装，避免无意升级依赖：

```sh
cd dashboard
npm ci --ignore-scripts --no-audit --no-fund
npm run build
```

需要交互开发时另运行 `npm run dev`；这是持续运行的开发服务，结束时按 Ctrl+C。普通样式、导航或交互修改，构建后从根 `dashboard.html` 离线打开，检查受影响操作、一个相关失败分支、键盘焦点及1024px窄窗，并确认没有意外远程资源请求。

`npm run build` 检查动作镜像，执行 TypeScript 和 Vite 编译，将脚本和样式内联进 `dist/index.html`，并检查离线资源。它不默认运行用户旅程或发布审计。需要时选择：

- `npm run check:journeys`：隔离首次创建、学习保存与召回、Skill 接入。
- `npm run check:upgrade-cli`：隔离升级、数据保留与局部容错。
- `npm run check:snapshot-source` / `check:snapshot-sync`：数据投影和快照事务。
- `npm run check:release`：准备正式发布时集中核对关键旅程、许可证与公开边界。
- `npm run analyze`：只生成本地包体分析，不用于最终安装。

这些是贡献者或维护者的检查，不是普通用户安装、升级或继续聊天的门槛。需要 TypeScript 或安装依赖元数据的开发检查，应在开发/隔离验证副本运行，不能要求已安装实例补齐整个前端工具链。

随包字体为未修改的 MiSans WOFF2，来源、字节摘要和许可见 `public/fonts/font-manifest.json`。程序、字体、图标和许可材料都从本地加载，不依赖 CDN。不要删除 `scripts/make-offline.mjs`，否则 `file://` 可能因本地 ES 模块限制无法打开。

运行依赖变化后执行 `npm run licenses:generate` 并审核第三方声明；新公开文件通过正式文件归类后刷新 `npm run compliance:manifest`。发布文件集合来自已跟踪源码，未提交的新文件不会自动成为正式候选。无 `.git` 的源码包按随包分发清单核对实际文件；不能把私密维护资料、工具缓存或 `node_modules` 打入安装包。

Agent 需要从正式资料重建快照时，可在项目根调用：

```sh
node dashboard/scripts/sync-snapshot.mjs
```

该入口从正式来源构建并同步快照，不把显示数据反写成用户资料。

## 分发与使用边界

公开模板的身份未选择，正式积累为零。在线演示使用单独的虚构资料，并清楚标示演示身份；示例不进入安装包。客户端与网页同样只读查看、复制请求。电脑窗口是当前支持目标，不宣称手机或未经实机验证的平台已经可用。
