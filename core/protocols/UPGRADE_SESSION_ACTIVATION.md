# 升级后的长期对话接续与宿主会话激活

本协议只在三种情况读取：AI Carry 产品文件在当前会话中完成切换；已实例化实例开始一项新的实质工作时，本次会话严格启动基线中的 AI Carry 产品版本或 manifest 摘要与当前严格启动胶囊不一致；或一个新运行明确接续尚未完成的升级。它补齐“文件已经安装”和“当前对话已经采用新版规则”之间的空白，不改变实例资产、组件或升级文件事务，也不建立后台轮询。宿主产品版本属于宿主观察，不参与 AI Carry 版本比较。

## 1. 五个事实不能混成一个“完成”

升级依次区分：

1. `source-verified`：目标来源、标签、Release、发布清单与解压树已经核对；
2. `files-installed`：隔离候选中的目标产品文件和实例保留内容已经验证；
3. `instance-switched`：稳定入口已经切到验证后的目标核心，实例身份与胶囊有效；双快照另报 `current` 或 `pending`；
4. `session-activated`：当前对话已经从目标版本启动、宿主完成了可验证的指令链重建，或当前长期对话在安全工作节点完成了有界的新版产品规则接续；
5. `behavior-accepted`：Agent 已自动验证目标版本声明改变的一项代表行为。

只有前五项都成立且双快照为 `current`，才可以对用户说“升级完整完成”。版本号、启动胶囊、快照、静态字符串或在旧会话中普通地重新打开新版 `AGENTS.md`／`BOOTSTRAP.md`，只能证明磁盘内容，不证明当前对话已经完成产品规则接续，更不能冒充宿主重建了系统级指令链。

`session-activated` 是 AI Carry 的当前对话采用状态，不等于声称宿主内部提示词已经被改写。宿主级重建只是更强的一种证据，不是所有 Agent 都必须具备的能力。

## 2. 当前长期对话是默认接续路线

已验证的文件切换完成后，Agent 不把验收工作交给用户，也不默认要求新建任务。它在当前原子操作已经结束、没有升级写入仍在进行的安全工作节点，按以下顺序自动接续：

1. 保留升级前记录的会话产品版本、实例 ID 与 manifest 摘要；
2. 在模型上下文外重新运行严格启动入口，只取得目标版本、同一实例 ID、当前 manifest 摘要和固定启动引用；
3. 只有严格启动结果与刚完成的升级事务一致时，才读取目标版本的最小启动入口、会话激活协议和本次发布说明中的相关变化；不加载全部记忆、SOP、能力、宿主档案或其他无关正文；
4. 保留当前对话、用户目标、已确认边界和任务进度，只更新 AI Carry 的可重载产品规则，不重新实例化、不清空上下文、不覆盖用户资产；
5. 检查当前宿主不可变规则是否与目标行为冲突。没有冲突并完成上述闭环时，记录一次临时的 `validated-current-session-reentry`，允许当前对话进入自动行为验收；有冲突时如实保持待接续，不能靠措辞假装已经采用；
6. 由 Agent 自动选择一项无破坏、前提真实且最能代表本次变化的行为完成验收，并向用户返回结果回执。

当前会话已经有同一版本和 manifest 摘要的有效回执时立即结束，不重复加载。长期对话开始一项新的实质用户目标时只比较严格启动胶囊的极小控制字段；没有变化就继续原任务，不扫描整个项目。升级发生在当前任务中时，在文件事务结束后立即进入本路线；外部变化只在下一项实质工作开始前接续，不在一个原子动作中途突然换规则。

普通文件重读、上下文摘要、模型自称“已经理解新版”、静态字符串命中，或把自己填写的 `passed`／版本号直接传给判定函数，都不能生成 `validated-current-session-reentry`。目标升级器声明 `sessionReentryCommand` 时，只执行该次 `confirm` 返回的精确命令；它从已切换根核对同次事务引用、变化文件回滚包、严格胶囊、manifest 摘要和代表路线，并单独报告双快照状态。核心有效即可接续，缺失或损坏的看板只需定向重建，不得阻止采用新版规则；看板尚未恢复时不能宣称升级全部完成。这条本地命令不得签发 `sessionActivated=true` 或 `behaviorAccepted=true`，也不能把无密钥摘要叫作宿主权威证明。只有宿主确实执行了规则重载或代表行为时，宿主侧适配器才能提交与同次事务绑定的观察回执；判定器只是分类这些宿主事实，不负责认证任意调用者自填的角色。没有可信宿主事实时保持待接续，实例与无关能力继续可用。

## 3. 宿主限制只影响接续方式

若宿主把旧版启动规则固化为当前对话不可替换的高优先级内容，或者无法运行严格启动入口：

- 不把它当成文件升级失败，也不回滚已经验证通过的目标实例；
- 当前对话继续提供普通交流、只读检查和不依赖新版语义的能力；
- 宿主支持真实原地重载时，由 Agent 自动执行并验证；
- 宿主只能创建全新运行时，可由 Agent 在不打断当前工作的前提下自动验证目标版本下次启动是否正常，但不能因此谎称旧对话已经采用新版；
- 两种能力都没有时，清楚说明“文件升级已经完成，当前对话将在下一次自然打开时采用新版”。不要求用户亲自执行升级验收；只有用户明确希望立即使用受影响的新行为时，才把新会话作为最后兼容路线并说明原因。

从尚未包含本接续规则的旧版本升级时，某些宿主可能需要一次新运行才能取得稳定的版本检查入口。这是一次性兼容过渡，不是后续每次升级的固定流程。

## 4. 自动行为验收必须真实但保持轻量

行为验收只选一个最能代表本次变化的场景，由 Agent 自动执行并报告，不要求用户输入测试提示词、检查文件或判断内部状态。

- 有真实、无破坏前提时实际触发；
- 行为会写用户数据、发送外部内容或需要新的高影响授权时，只验证到后果发生前的路线与门禁，不能借验收扩大授权；
- 发布说明若没有提供可安全自动验证的代表路径，保持行为待验收并报告这是发布资料缺口，不伪造用户选择、错误、资产或结果；
- 纯文件或内部修复若发布说明明确没有运行行为变化，可用一次严格目标启动／路线结果代替。

不为每个宿主、每个字段、每个资产建立矩阵。发布前只保留少量高信息量场景：普通重读不能冒充接续；长期对话可以接续；新运行仍能启动；行为失败只影响该项结论；磁盘启动真源无效才回滚；缺失事实安全降级。

## 5. 用户回执与失败范围

升级完成回执至少用自然语言说明：原版本与目标版本、来源和文件是否通过、实例与用户内容是否保留、当前对话是否采用新版、自动行为验收结果、仍可用范围，以及用户总体目标中的下一项真实工作。用户无需再亲自运行一遍测试才能知道是否升级完成。

- 来源、目标树、核心切换、实例身份或启动胶囊无效：按升级事务恢复触碰过的核心文件。仅双快照刷新失败时保留有效新核心，标记看板待刷新并定向重试。
- 文件与实例切换有效，但当前对话尚未接续：保留新实例，不回滚；只把当前对话采用状态保持为待接续。
- 当前对话已采用目标版本，但代表行为未通过：保留实例与证据，由 Agent 定向修复或在下次真实使用时复核；普通对话、只读能力和不依赖该行为的功能继续可用。
- 无论进入等待、自动重试、局部失败或回滚，都说明发生了什么、影响范围、数据是否安全、仍可使用什么和推荐下一步。

完成状态不得靠降低校验、假造行为、反复重启、删除失败现场或把“我重新读过文件”改写成宿主热加载来获得。
