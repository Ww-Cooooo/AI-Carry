# 渐进上下文路由

本协议只在用户用近似日常说法召回以前的做法、出现多个相似候选，或路由异常、能力找不到、上下文过载、维护路由系统时读取。普通且目标明确的任务只执行 `BOOTSTRAP.md` 和地图元数据，不加载本文。

## 固定结构

AI Carry 只有三层：

1. 根地图：判断任务属于哪个类别。
2. 分类地图：查看小型路由元数据，选出候选能力。
3. 目标正文：读取真正执行任务所需的协议、SOP、能力、记忆或指南。

不得增加“必须先读的第四层”。目标正文也不得为了声明“何时不读我”而进入普通上下文；是否读取必须由上一层地图的触发元数据决定。

`core/maps/trigger-registry.toml` 是维护盘点，不是普通请求的新路由层；`instance/maps/time-trigger-map.toml` 是日期命中后的非启动索引，也不是每次必经层。普通请求仍是根地图 → 分类地图 → 目标正文，只有恢复、到期或当前事件确实命中时才旁路读取相应小型状态。

动态启动胶囊中的 `instance/maps/signal-map.toml` 是当前运行状态的极小投影，不是内容发现层。它只能指向根分类和路线，不能绕过根地图、分类地图直接扩展为第四层，也不能携带完整规则或资产正文。

## 混合选择

- 明确关键词、稳定动作 ID、文件类型或实例方向可由确定性规则直接匹配。
- 实例资产路线可用 `asset_kind`、主题、对象、别名、范围、条件和关联 ID 做小型候选漏斗；这些字段只用于发现，不能代替目标正文的执行规则。`asset_kind = "task-family"` 是任务导航的非资产路由标记，可指向 manifest 登记的实例说明或扩展清单登记的工作区入口；按需加载，不计入正式资产、成熟度或看板资产计数。
- 规则得到多个合理候选或无法判断语义时，才让模型在候选元数据之间做选择。
- 没有候选时只回退一个相邻分类地图；仍不确定便向用户问一个能改变路线的问题。
- 一个任务确实需要多个能力时可以组合少量路线。例如“联网查资料并形成正式记忆”同时需要外部安全、领域工作和资产生命周期。
- 实例资产的 `active` 路线正常参与选择；`provisional` 只有在当前范围和条件精确匹配时作为可撤销试用参与，不能覆盖冲突的 active 资产或授权高影响动作；`candidate`、`review` 和历史正文不进入普通稳定路由。

## 日常语言怎样召回以前的做法

持续任务的资料留在原工作区或本地资料层，不必晋升为记忆或 SOP。保存时按 `USER_GUIDANCE.md` 第 4.1 节接好已有任务入口，不能只写文件却留下断链。续接时从命中的入口读取当前索引，再按需读取相关正文；先核对用户认可、已完成／撤回和仍待做的状态，再选择下一项。不能按最新文件或编号直接续做，确实需要重做时说明原因。入口缺失只修当前任务，不复制第二套记录或把全部历史常驻加载。

相对链接是导航线索，不是扩大读取权限。跟随前以当前文件为基准解析，只读取本次任务授权的资料，核对实际边界与链接；缺失时只修复这条入口或说明缺口，不猜测历史、不让全部召回失效。当前设备的绝对位置留在本机说明或绑定中，便携入口只留必要相对引用。

用户不需要记住资产标题、稳定 ID、文件路径，也不需要先判断“这是一条记忆还是一个 SOP”。“帮我弄一下学习通上的成绩”“按上次那个办法整理”“我记得以前做过类似的”都属于正常任务表达，不是路由失败。

处理顺序固定为：

1. 从当前请求提取一个极小任务特征：想完成的结果、对象、明显动作、用户自己的说法、已知环境和排除条件；不把整段对话复制进地图。
2. 只在实例领域地图中比较 `title`、`summary`、`triggers`、`aliases`、`topic_key`、`subject_key`、`scope`、`conditions` 和 `excludes`。这一轮不读取资产正文，也不枚举其他目录。
3. 只有一个高置信候选且没有范围冲突时，使用用户当前交流语言确认：“你以前保存过【人能看懂的标题】，这次看起来很接近。是不是继续按这个做？”用户确认后才只加载该目标正文和登记的必要依赖；用户说不是时继续按新任务或补充信息处理。只有用户已经明确点名这项已保存做法，或点击带稳定 ID 的看板动作时，才按普通确定性路线加载，不额外重复确认。“帮我弄一下学习通成绩”“按以前那种方式”之类只有目标、对象或近似说法的请求，即使恰好只返回一个候选，也不属于明确点名，仍先做上述一次确认。
4. 有 2～3 个合理候选且选择会改变做法时，按可能性给出人类可理解的差别，例如结果、对象或适用范围；让用户选“第一个、第二个、都不是”或用自己的话补充。不要展示文件名、稳定 ID 或内部评分。
5. 初次比较仍有 4 个以上合理候选时，先只用结果、对象、`scope`、`conditions`、`excludes` 和状态再收窄一次，不读取任何正文；仍超过 3 个时只展示差异最大的最多 3 项，并提供“都不是／我再补充一点”。不得任选四个之一，不得把其余候选写成持久状态，也不得为消除歧义打开全部正文。
6. 没有可信候选时继续按新任务处理；只在确实缺少会改变结果的信息时问一个问题，不能因为用户说得不专业就要求其先学习 AI Carry 术语。

“高置信”不能只靠一个宽泛词相同。执行模型必须同时核对：用户想得到的结果是否一致；对象或主题是否一致；当前条件是否落在 `scope`／`conditions` 内；`excludes` 是否没有命中；资产状态和确认门是否允许本次使用。像“成绩”“文案”“整理”这种单个通用词只能帮助找候选，不能单独决定沿用。即使只有一个候选，只要它会改变高影响决定、输出对象仍可能不同、条件缺失或用户明确表示不确定，都应先用用户当前交流语言简短确认，而不是直接执行。弱模型也不得因为无法计算数值相似度就退回精确口令；按这些语义条件逐项判断即可。

资产形成或真实使用后，应把用户实际会说的低敏表达整理为少量 `triggers`／`aliases`，并保留适用范围与排除条件。不得保存包含隐私正文的原句，也不得为提高“命中率”无限堆积同义词；每类字段建议不超过 8 项。误命中、用户说“不是这个”或范围变化是修正路由元数据的学习信号，但不是自动覆盖正式资产的授权。

## Agent 工作时怎样主动想起

召回不能只等待用户说出旧资产的关键词。每个任务首次路由，以及当前目标、下一项有实质影响的行动、已验证状态／异常、到期信号、已选资产关联或任务结果发生改变时，Agent 把用户原话与少量当前工作线索交给同一个有界检索入口。工作线索只描述当前要做什么、对象是什么、已经核实的条件或发生了什么变化；不复制完整对话，不增加新的路由层，也不为普通机械步骤反复查询。

用户原话、当前工作线索和一次有界意图改写作用不同：用户当次否定、纠正和 `excludes` 永远优先；工作线索可以让已获明确批准、范围唯一且门禁允许的资产进入当前选择；意图改写只能在首次无匹配时帮助再缩小一次候选，不能单独授权自动沿用、高影响动作或正式写入。没有可信候选时正常按新任务继续；单条资产损坏只隔离该条并说明召回降级，不能让整个 Agent 停止。

判断排除项时区分“要求做某事”和“禁止做某事”，用户原话与当前工作线索都一样。例如“继续筹备；不要对外发送”仍可召回本地筹备资料，外发禁令继续有效；不能只因禁令含有 `excludes` 中的动作就排除整个任务。真正要求越界或明确拒绝沿用时仍按原限制处理；检索器只识别清楚的局部禁令，复杂或矛盾表达仍由 Agent 结合原话判断，不能删掉禁令来制造授权。

“继续”“下一项工作”之类泛化文字不能挤掉当前具体工作命中的候选。检索器在原有最多三项内保留工作线索最相关的一项；排序只用于发现。出现词面与工作上下文分歧时，Agent 比较这些元数据中的目标、范围和排除条件后选择，不把歧义当全局失败或一律问用户；只有缺少会改变结果的用户选择才提问，既有读取与动作授权边界不变。

已确认、低风险且范围明确的 `habit` 不需要每次重复征求同意。检索器只缩小候选，不替 Agent 理解语义：遇到 `assess-confirmed-habit-scope`，用当前任务核对目标、对象、条件和排除项，确定适用后按现有选中 ID 入口加载；不复制触发词伪造匹配，也不降低相似度阈值冒充理解。即使标记为自动候选，仍要核对实际范围；用户否定或当前工作排除项命中时不采用。不确定时只问会改变结果的问题，或继续按当前要求完成任务；其他资产仍遵守各自确认边界。

每个任务的第一次工作更新都要用用户当前语言说明本次是否使用了长期资产。实际读取并用于当前工作时，用独立短卡而不是埋在长段落里；标题固定为“🧠 这次用上了”，不得省略或随意替换大脑图标，通常只列 1～3 个短点，每项写人能看懂的资产类型／名称、由什么当前信息触发，以及它具体怎样影响这次做法。例如：

> **🧠 这次用上了**
>
> - 记忆：先读现有路线——当前准备修改产品规则时命中，让我先核对既有约束再落地。

读取正文后先判断它会怎样改变当前的具体选择，或为什么本次不适用；不能只复述标题或“我会注意”。中途新增实际使用时才增量说明，任务结束不重复播报。只列出候选但没有读取正文，或已经读过但没有采用，都不能声称已经使用；没有使用长期资产时用一条独立短句说明。使用卡是过程透明回执，不证明结果有效；最终回复中若有使用卡，必须放在本地化 `👉` 下一步区块之前。默认不展示内部评分、稳定 ID、文件路径、哈希或触发源代码；这些只在用户确实需要排查时提供。

长任务进入最终交付，尤其经过上下文压缩或续接时，在现有任务摘要中保留相关经验造成的关键取舍、用户否定和未验证结果，不复制整份经验。只把本任务实际使用项的标题、作用和已回执状态交给 `task-closeout-contract`，不重新加载资产正文或扫描历史。它只核对回执是否缺漏，不验证应用是否恰当或任务是否成功；检查器缺失或输入损坏时从当前任务证据重建必要回执并继续交付，不能让元数据小故障吞掉业务结果。

## 最小充分上下文

路由目标不是读取最少，而是让模型得到完成任务所需的最小充分信息：

- 必须保留用户要求、实例边界、安全约束和验收标准。
- 只读取当前步骤需要的正文；进入下一阶段再读取下一份。
- 长任务可以使用本地任务包传递明确事实，不把完整聊天历史交给执行模型。
- 如果输出质量下降、遗漏关键约束或多次走错路线，应允许回溯、增加一个候选或向用户澄清，不能为了省 Token 硬做。

## 速度边界

普通明确任务应在根地图和一个分类地图后进入目标，不先扫描仓库、不建立向量库、不运行后台索引。实例领域地图按 Map Schema 固定使用 32 KiB／96 条软线、48 KiB／128 条硬线和最多 3 个候选；每次相关正式变更顺带检查，绝不截断后假装完整。全文检索、RAG 或向量索引只有在记忆规模、地图容量或检索质量触发 Level 3 评估且用户批准后，才作为本地可重建派生层启用。
