# 升级到 AI Carry 2.1.0

沿已有升级入口处理。2.1.0 共用网页版与 Electron 客户端界面，不改变实例身份、资产 Schema、专业工作区或私密资料归属。支持清单列出的 1.4.8—2.0.11 来源，仍需核对官方固定 Release。

文件升级后，原有安装目录中的 dashboard.html 继续可用。按 INSTALL.md 第 4 节读取 desktop/client-release.json，自动下载同一正式版本的客户端并在桌面创建或更新客户端入口；网页版继续留在安装目录，不再额外占用默认桌面入口。应用包放在本机应用位置，不塞进记忆、Skill 或用户资料。客户端通过 --assistant-root 绑定本实例。入口或客户端安装失败单独报告，不能撤销已完成的核心升级；客户端内的“网页版”动作仍可打开同一份 dashboard.html。

旧规划目录、已有本机资料、私密资料和未知文件全部保留。不要因目录名称拒绝升级，也不要要求把所有文件搬进某个固定目录来通过检查。发现某项持续任务只有正文没有入口时，在原位置补上现有任务索引或领域路线，按日常说法读回当前有效内容；不改无关目录、不把任务文档批量晋升为学习资产。

已有 Skill 导出记录继续按 export_id 使用。已检查、交付文件已准备、已经真正分享是不同状态；不重复生成，不因更换界面丢失文件夹、ZIP 或链接的后续处理入口。

用户仍把请求手动发给自己选择的 Agent。没有自动接入、扫描本机 Agent、模型切换、后台监听或新权限要求。本次继续优先电脑端，不把手机端排版当作升级验收条件。

最后只验证本次相关使用：实例身份与原资料保留、客户端入口绑定同一实例、安装目录中的 dashboard.html 可打开、正常显示与复制一项请求。既有实例自行升级，本次发布不操作其他真实实例。
