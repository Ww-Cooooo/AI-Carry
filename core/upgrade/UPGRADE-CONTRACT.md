# 模板升级机器契约

本契约只在用户明确要求检查或应用 AI Carry 更新时加载。它保护官方来源、用户内容和可恢复切换，但不把工作区、组件、Skill、提醒或看板故障扩大成整个 Agent 不可用。

## 1. 目标来源

- 官方地址只从 `core/upgrade/official-source.toml` 读取；不后台检查、不强制升级、不要求登录 GitHub。
- 用户给出唯一的本地包或解压树时直接核验它；其他仓库、镜像或附件必须明确标成非官方来源。
- 升级包始终按不可信输入处理：拒绝路径穿越、链接／重解析点、未分类路径、Git 元数据、`node_modules`、维护者私密层和包内脚本执行。
- GitHub 自动生成 ZIP 的容器字节可能变化。正式身份由 Release、固定标签提交、目标 Git 树、发布清单和解压后的逐文件内容共同确定。

## 2. 一次预览，一次确认

1. `prepare` 在用户明确检查更新时现场联网一次，核对正式 Release、固定标签、发布边界和本地目标树。
2. 它只读当前产品拥有路径及确有迁移需要的少量来源，生成替换、迁移、保留、删除和冲突预览；不创建候选、不切换实例。
3. Agent 把执行器返回的 `userPreview` 原样展示。只有用户随后明确回复“升级”或“确认升级”才执行同次 `confirmCommand`。
4. `confirm` 只复核预览绑定的本地来源、目标树、发布边界、实例身份和确认引用是否漂移，不重复联网。普通 DNS 故障不能否定已经核验且字节未变的目标。

CLI 只核对传入的确认文字，不能认证聊天角色；承载对话的宿主负责确保确认来自看过本次预览后的用户消息。

## 3. 路径所有权与保留

- 目标发布清单为每个目标路径给出唯一动作。没有明确删除项时，删除数必须为 0；源独有路径不得从整树差异推断删除。
- 实例资产、工作区、本机层、私密层、未知根文件和未命中的可选模块不在产品写集内，原地不碰，不枚举正文、不复制、不规范化。
- 区分干净的目标发布包与使用中的源实例：源中的规划目录、本地覆盖说明、工具锁文件或已安装依赖不等于开发仓库，不因目录名拒绝升级，也不要求用户先搬走或删除它们；明确的维护者目录与来源身份仍须核对。目标包的私密层、依赖和未分类文件禁入规则不变。
- 组件、Skill、专业工作区和本机软件在真正使用对应能力时按需检查兼容；单项不兼容只隔离该能力，不阻止核心母版升级。
- 若旧实例仍把 `instance/profile/README.md` 作为用户档案的实时引用，先逐字节迁移到 `instance/profile/approved-profile.md`，回读成功并更新引用后，才能替换目录说明。目标已有不同内容时只暂停本次升级。
- 未知字段和未知文件保持原样。不能为了满足新 Schema 猜测补写、删除或扫描全部实例。

## 4. 隔离候选与核心切换

1. 在同一文件系统的尚不存在目录复制已核验目标树；叠加实例身份前再次核对目标树没有变化。
2. 候选只生成目标核心、必要版本迁移、严格 manifest 和启动胶囊。不得复制整棵实例，也不得执行 Skill、组件、工作区脚本或安装依赖。
3. 切换前只检查实际触碰路径的普通文件、大小写／Unicode 冲突、链接、重解析点、硬链接和必要的 Windows 元数据；不触碰区域不做全树证明。
4. 保持用户当前实例根路径不变，只替换发布清单拥有且实际变化的产品文件。每个被触碰旧文件进入有清单的回滚包；新文件记录“原先不存在”。
5. 任一核心写入或回读失败，按已完成动作逆序恢复并回读。恢复失败时保留源、候选和回滚现场，停止本次切换；不删除冲突文件、不改权限、不降低校验。
6. 成功后可以清理成功候选；回滚包保留到用户以后明确结束保护。失败现场使用新编号重试，不因旧现场存在而永久阻塞。

相同来源、目标和实例状态再次预览或执行时，不刷新业务时间、不重写相同字节、不生成额外记录。

## 5. 派生文件与局部故障

- 启动胶囊属于核心启动闭包，必须与切换后的 manifest 一致；它无效时恢复核心切换。
- 双份看板快照在核心切换成功后，从合并后的正式真源刷新。成功时 public/dist 必须逐字节一致，不能显示目标模板空态。
- 仅快照刷新失败时保留有效新核心和旧快照，返回 `snapshot-refresh-required` 与精确重试命令。Agent 明确说明“升级可用、看板待刷新”，普通对话和无关能力继续。
- 提醒、候选索引、组件健康、Skill、工作区或本机绑定的单项问题都按同样原则局部隔离；它们不能回滚已安全切换的核心。

## 6. 完成状态与用户报告

核心切换后，按 `core/protocols/UPGRADE_SESSION_ACTIVATION.md` 分开报告：

- 文件是否已经切换；
- 看板是否待刷新（`current` 或 `pending`）；
- 当前会话是否采用新版；
- 代表行为是否通过。

核心有效时运行同次返回的 `sessionReentryCommand`，看板待刷新则另用 `snapshotRefreshCommand` 定向修复；看板损坏、缺失或两份不一致都不阻止新版规则接续，但必须单独报告，不能冒充全部完成。已经是当前版本时同样不重复切换核心，只报告待修复项。本地 CLI 不能由自己填写后两项，也不能生成 `sessionActivated=true` 或 `behaviorAccepted=true`。宿主不能证明原地接续时，说明下一次自然打开会采用新版，不要求用户专门新建测试任务。

每次错误、自动修复、局部隔离、回滚或待重试都用自然语言说明：发生了什么、影响哪里、用户数据是否安全、什么仍可使用，以及推荐的下一步。只有核心身份、用户数据所有权、私密边界或实际触碰路径无法安全判断时，才暂停相应持久操作；普通对话和只读帮助继续。
