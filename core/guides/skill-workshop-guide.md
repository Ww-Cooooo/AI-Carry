# Skill 工坊

Skill 工坊只做两件事：把用户主动选择的已验证方法整理成可分享 Skill；把别人分享的 Skill 安全接入当前实例。普通学习、保存 SOP、使用能力或看板推荐不会自动触发转换、上传或安装。

原始 SOP／能力仍由资产生命周期管理；可编辑的本地 Skill 草稿是转换后的内容真源；ZIP 和独立文件夹只是交付载体。安装后的 Skill 由 `instance/skills/requirements.toml` 按需登记。本机软件、模型和组件仍走实例兼容协议。

## 1. 推荐什么

- 优先推荐流程清楚、已经实际验证并得到用户授权的 SOP。
- 能力只有确实包含可重复流程时才推荐；经验应先提炼为方法。
- 记忆、身份、偏好、私密正文、候选、待办、治理卡、验证记录、本机软件和组件登记不直接转成 Skill。

推荐只是解释“为什么可能值得整理”，不是待办或强制动作。用户不转换不会影响原方法、成熟度和普通工作。

## 2. 从方法生成 Skill

动作 ID：`skill.create-from-asset`。

1. 根据看板给出的 ID 回读真实资产；找不到、类型不符、尚未验证或授权不清时，只说明缺什么，不猜目标。
2. 用户没有说明分享方式时，只问一次：推荐 ZIP，也可以选择独立文件夹、链接或只保存在本机。链接只先准备本地 ZIP；上传到哪里、谁能看到仍要另行明确。
3. 使用工坊内置创作核心：先从当前对话和正式资产提取用途、触发与不触发场景、输入、预期结果和真实依赖；只询问仍缺少且会改变成品的内容，不让用户重新讲已经说过的流程或填写内部字段。
4. Agent 在 `instance/skills/exports/<skill-id>/` 建立本地隔离草稿。自动脱敏、通用化和参数化只作用于这份副本：移除实例身份、真实人名／项目名、绝对路径、私密引用、秘密凭据和一次性参数；原方法保持不变。
5. `SKILL.md` 的 `name` 保持短而稳定，`description` 同时说明“做什么”和“什么任务会用到”，但不吸引无关任务。正文用自然语言保留关键步骤、失败处理、边界和验收；只在确有用途时加入 `references`、`examples`（示例）、`scripts`、`assets` 或可选宿主元数据，细节按需加载，不把简单流程填成字段表或附带空目录。示例与其他内容接受相同的隐私、路径和内容检查，不因目录名获得信任。
6. Agent 自动检查结构、隐私边界、2～3 个真实代表触发和一个容易误触但不应使用的场景。结果可客观核对且流程确实复杂时，再运行一条隔离代表任务；普通 Skill 不建立批量基线、评分 Agent 或统计评测。检查可以读取脚本文本，但不能执行脚本、安装依赖或联网。
7. 本流程不安装、更新或依赖外部 Skill Creator。当前宿主已经提供原生 Creator 且复杂 Skill 确实需要时，可以把它作为草稿后的可选复核并如实说明；不可用或失败就回到内置流程，只影响当前复核。检查通过后按已选方式生成一个不覆盖旧版本的本地载体，并报告绝对路径；生成或登记失败只保留当前草稿、已完成载体和失败现场，不改原方法，也不影响其他 Skill。

导出索引只在第一次真实生成时建立。稳定共享身份用于以后识别“同一 Skill 的新版”，并与版本一起写在标准 `metadata` 内；版本只在内容真实变化时前进。同一内容重复操作复用现有结果，不为了时间或格式制造新版本。用于防止包在检查后被替换的内容摘要保留在工具内部，不作为用户理解或日常运行门。

## 3. 继续已有草稿或未分享 Skill

动作 ID：`skill.continue-export`。

- 看板状态只作定位线索，Agent 先回读当前真实条目；状态已变化时解释后按现状继续，不强行改回旧状态。
- 草稿未检查完：继续检查这一份；检查通过后只补问缺失的分享方式。
- 已检查但未分享：直接生成 ZIP／文件夹，或在链接目标与可见范围明确后继续链接分享。
- 旧版“已生成但未分享”条目必须能够无损继续；不要求用户重做 Skill，也不因缺少新字段而失效。
- 真源变化后旧载体仍保留，新载体使用新版本；远程链接失效只影响该链接，不删除本地真源或旧载体。
- 索引仍写“可以交付”但本地 ZIP／文件夹已经不存在时，只把这一项显示为“载体已失效”；可编辑 Skill 草稿和其他 Skill 继续可用，用户需要时由 Agent 从现有草稿重新检查并生成新载体。
- 条目损坏或身份无法判断时，只隔离这一份导出并给出修复入口；看板、对话和其他 Skill 继续。

## 4. 安装或升级别人分享的 Skill

动作 ID：`skill.install-shared`。

1. 用户可以给本地文件夹、ZIP 或唯一可取得包的链接。本地路径优先；来源不唯一时用一句自然语言帮助用户找到它，不扫描整台电脑。
2. 外部 Skill 始终视为待核验内容。统一通过 `dashboard/scripts/skill-install-cli.mjs prepare` 在本机有界检查结构、秘密、越界路径、链接、脚本、依赖和兼容性；ZIP 解到新的隔离目录。检查不执行脚本、不安装依赖、不登录、不自动改写外部包。
3. `ready` 显示一次普通语言预览；`review` 解释需要用户判断的权限、二进制或兼容项；`isolated` 只隔离危险或破损的这一包。用户看到本次预览并明确安装／升级后，复用执行器给出的确认入口，不让用户填写内部字段。
4. 第一次安装把包原子复制到 `.assistant-local/skills/`，回读成功后才登记；空模板 requirements map 在这里懒初始化。失败恢复旧登记并保留原共享包。
5. 同一稳定 `skill_id` 且版本更高时，Agent 明确告诉用户这是升级，并展示新增、修改和移除内容。确认后替换本机副本；同版本不同内容、降级、同名不同身份或本机副本被手工修改时，两边都保留，只暂停这一项并解释选择。
6. 包内容、来源、当前已安装副本或实例身份变化时，旧预览失效并重新检查。内部内容摘要只用于证明确认的还是同一包，不展示成用户任务，也不能让一个 Skill 的问题拖死 AI Carry。
7. Skill 额外需要软件、模型、权限或新组件时，再命中相应安装和兼容边界；不能把这些动作偷偷并入“安装 Skill”。

安装主体成功而看板刷新失败时，报告“Skill 已安装／升级，看板待刷新”并允许稍后重试；不能撤销已经回读成功的安装。任何自动修复、降级或隔离都要用自然语言告诉用户发生了什么、仍可使用什么以及推荐下一步。

## 5. 看板与迁移边界

`instance/skills/exports/index.toml` 只记录真实生成过的本地 Skill，不进入普通启动上下文。空模板不预创建它；旧条目和未知字段原样保留，相关动作发生时再补可唯一推导的信息。索引损坏不能从目录猜测用户意图，只暂停新的导出登记；已有目录和载体不删除。

看板要让用户一眼分清：Agent 推荐整理的 Skill、本地草稿、可以分享、需要复核、已安装以及可升级。每个状态用日常语言解释原因和下一步，不只显示内部名词。

`instance/skills/**` 属于实例内容，母版升级和换机默认保留；`.assistant-local/skills/**` 是本机安装副本，换机后按登记重新绑定。公开空模板只携带工坊能力和空的 requirements 模板，不能包含用户生成的 Skill、私密内容或本机路径。

## 6. 完成回执

完成后简短报告：处理了哪一份 Skill、原方法／外部包是否保持不变、Agent 自动检查或脱敏了什么、实际生成／安装位置、脚本和依赖是否执行、局部问题及推荐下一步。学习回执和真正的 `👉 接下来` 仍按统一用户引导规则单独呈现。
