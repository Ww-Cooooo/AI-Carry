# 首次使用执行检查点

本文件不是普通启动正文，也不是另一套实例化流程。它只在四个临门时刻读取：安装完成后的第一条回复、首项真实任务开始前、用户确认创建后准备写入、首项真实任务结束后。命中时只读取对应一节，不把本文件常驻上下文。

## A. 安装完成后的回复门

首次进入创建时只检查一次运行条件：当前宿主能否读写目标目录，并用已存在的本机或宿主随带 Node.js 运行下面的只读 `--help`。缺少运行时或执行权限就立即说明，保留已收集的选择；看板、对话和创建方案仍可继续。下一步推荐换到具备本地执行能力的宿主，或经用户同意后配置运行时；不自动安装、不改权限、不另造写入器，也不把“文件已安装”说成“助手已创建”。同一环境已有成功调用证据时复用，不重复检查。

当空白模板已可用、清单仍为 `template`，准备第一次回复用户时，必须同时做到：

1. 先邀请用户创建自己的 AI Carry，而不是用安装技术报告结束。
2. 同时给出看板和当前聊天两个入口；看板没打开也不能阻断聊天引导。
3. 用自然语言解释三种交流方式适合谁，再只问一个容易回答的问题；用户也可以直接描述职业、困难和目标。
4. 来源、安装位置、入口、模板状态和没有执行的高影响动作放在简短摘要里，不用文件数量淹没用户。
5. 回复末尾给出真实下一步，不能让用户误以为安装文件就绪等于首次创建已经完成。

缺少其中任何一项时，按 `core/guides/instantiation-guide.md` 补齐后再发送。安装入口有局部问题时，如实说明具体影响并继续聊天引导；只有模板本身不可用才暂停创建。

## B. 首项任务开始前的实例化交接门

当清单仍为 `template`，用户已经选中或基本确定第一项任务，当前 Agent 准备索取真实任务数据或开始执行时：

1. 用户必须先明确选择 `general` 或 `domain`；“先帮我判断”只是引导，不是第三种正式方向。
2. 模板态只能讨论目标、所需材料类别和人工判断边界，不能把未执行任务写成资产或验证记录。
3. 模型等级是任务复杂度建议，不是首次创建授权。确定性执行器负责正式写入；当前 Agent 能准确收集选择、展示完整预览并解释结果时即可继续。只有确实出现需要跨组件权衡的复杂架构问题，才建议更强模型或转交专项复核，且不丢失已收集信息。
4. 按本文件 C 门完成创建后，才索取真实业务数据并开始首项任务。用户只想临时完成普通任务时可以暂停创建，但必须说明这次不会自动成为长期积累。

## C. 实例化写入门

### 进入条件

- 已按 `core/guides/instantiation-guide.md` 取得最小充分信息；
- 当前 Agent 已把确认语义保存为不超过 64 KiB 的临时 UTF-8 JSON 请求；
- 已运行确定性执行器的只读预览，并把返回的 `user_preview` 原样展示给用户；
- 用户明确确认的是完整预览，而不只是某个任务名称。

### 唯一正式写入口

复用 A 节已确认的运行条件，先查看准确用法和字段形状，不照抄示例，不写入秘密凭据：

`node dashboard/scripts/first-instantiation-transaction.mjs --help`

`node dashboard/scripts/first-instantiation-transaction.mjs --example`

只读预览：

`node dashboard/scripts/first-instantiation-transaction.mjs --root "<AI Carry 根目录>" --request-file "<临时请求 JSON 文件路径>"`

用户确认后复用同一个请求文件：

`node dashboard/scripts/first-instantiation-transaction.mjs --root "<AI Carry 根目录>" --request-file "<临时请求 JSON 文件路径>" --write --acknowledge-complete-preview`

模型不得逐文件手写正式清单、索引、胶囊或快照，也不得因执行器报错而临时发明替代脚本。`first_task.start_after_instantiation=true` 表示完整预览确认已经包含“创建后直接开始首项任务”，不重复询问。

### 核心原子写集

首次创建只原子写入三个相互依赖的真源：

- `instance/manifest.toml`：实例身份、锁定方向、交流方式和已确认策略；
- `instance/profile/approved-profile.md`：用户确认的范围、边界、环境假设和第一项任务说明；
- `instance/maps/domain-map.toml`：只登记指向上述档案的初始 `task-family` 路线。

执行器在同一文件系统中冻结这三个目标的前像、生成隔离候选、回读核心身份与引用，再整组替换。核心写入任一步失败时恢复这三个目标的原状态；失败只停止本次创建，不影响普通对话和模板外能力。

首次创建不预先初始化验证索引、候选索引、组件注册表、宿主档案、Skill 小地图、信号或治理日程，也不制造记忆、能力、SOP、经验、候选、验证记录或待办。这些内容由相应能力第一次真实使用时按需初始化；模板身份和空态不是创建失败。

### 可选投影与局部失败

核心创建成功后，执行器尝试刷新启动胶囊和 public/dist 看板快照。它们是可重建投影，不属于三文件核心事务：

- 成功时回读身份和双快照一致性；
- 失败时返回 `limited` 和具体待重试项，保留已经有效的实例；
- 看板或胶囊待刷新不能阻止普通对话、第一项任务、学习或其他无关能力；只在某项持久操作确实依赖失效投影时定向修复。

快照必须能够宽容读取仍处于模板空态的可选索引，并把它们投影为 0；不能为了生成快照伪造业务记录。刚创建且尚未完成真实任务时，memory、capability、SOP、experience、evolution、validation、todo、Skill、component 和 governance 均为 0，初始 `task-family` 不计入正式资产。

### 写后回读与幂等

向用户报告完成前只核对决定可用性的事实：

1. 三个核心文件使用同一实例 ID，方向已锁定，档案引用指向真实 `approved-profile.md`；
2. 初始任务路线存在且目标可读，没有预先制造正式资产或结果证据；
3. 若胶囊已刷新，其 manifest 来源与实例身份一致；若快照已刷新，public/dist 逐字节一致并显示空资产状态；
4. 第二次执行同一请求不改写核心文件、不更新时间、不增加任何记录；已有实例发生后续变化时不重置它。

能由正式 manifest 或当前目录事实唯一确定的可选身份、计数、排序或派生漂移，由对应能力在第一次使用时自动修复并自然语言报告；无法唯一判断时只隔离该能力，保留原字节并给出下一步。任何错误、自我修复或局部降级都必须告诉用户发生了什么、影响什么、保留了什么以及建议怎样继续。

## D. 第一项真实任务结束门

第一项任务和以后普通任务一样，先完成真实工作，不为了学习而拖慢用户。只有任务结束或用户反馈命中长期价值信号时才进入本节。

以下表达应视为明确的任务结束信号，而不是普通寒暄：

- “结果正确”“这次做对了”“我核对过了”；
- “以后继续这样”“以后可以继续使用”“把这套方法保存下来”；
- 用户明确要求形成记忆、能力、SOP 或经验；
- 用户指出失败、纠正或适用边界。

此时按顺序执行：

1. 读取 `core/protocols/RESULT_VALIDATION.md`，根据当前任务可获得的真实证据判断 `validated`、`limited` 或 `failed`；不要为了结案追加与风险无关的测试。
2. 命中长期价值时读取 `core/protocols/ASSET_LIFECYCLE.md` 和 `core/schemas/asset-frontmatter.schema.md`，只比较当前任务族和少量相关候选，不扫描全部资产。
3. 用户只确认结果正确时，不自动创建新资产；在自然停点用普通语言说明发现了什么并询问是否留下。选择“先观察”才建立最小候选，选择“不保存”或没有回应时不留下持久学习状态。
4. 用户明确说“以后继续使用／保存这套方法”且本次结果成立时，可以保存对应正式资产；新资产从真实证据支持的成熟度开始，不能直接宣称可靠。
5. 现有能力或 SOP 本次成功时更新同一资产的有界证据；同一任务的重试、改写和转发只计一次，失败或有限完成不增加成功次数。
6. 新资产必须有一条类型一致、直接指向正文的正式路线；初始 `task-family` 不能冒充正式资产。
7. 时间、计数和快照属于可重建元数据：写入器能取得时生成规范值，缺失或漂移时按真源修复；它们不能单独成为召回或普通使用的全局阻断理由。
8. 正文详细程度与任务复杂度相称，说明目的、触发与排除、关键步骤、权限边界、验证和失败处理；简单方法不填冗长空模板。
9. 正式资产保存成功后再尽力刷新相关索引、信号和看板。派生刷新失败只标记相关区域待重试，不撤销已经验证的资产正文。
10. 单独向用户给出简短的 `🧠` 使用回执和 `🌱` 学习回执；回复最后仍用明显的 `👉 接下来` 指向总体目标中真正未完成的工作。

如果当前宿主不能写入 AI Carry 真源，要明确说“这次方法尚未保存进 AI Carry”，并提供最小可继续方案；不能只在聊天里承诺以后会记住。
