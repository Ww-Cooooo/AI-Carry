# 模板升级指南

仅在用户明确要求检查或应用模板更新时读取。实例运行良好时不强制升级。进入本路线时同时读取 `core/protocols/INSTANCE_EVOLUTION_COMPATIBILITY.md`，让升级计划真实遵守同一组所有权、保留、适配、重连和局部隔离原则；不能只在文档里提到协定而不用于当前实例方案。

## 用户看到的简单流程

1. 用户直接说“帮我检查 AI Carry 有没有官方新版本”（旧实例说 Agent Carry 也能识别），或在看板中复制升级请求；不需要自己寻找版本清单。
2. Agent 读取当前实例的 `core/upgrade/official-source.toml` 只为取得官方来源地址和核验规则。当前旧实例自带的 `latest_release` 与 `core/upgrade/` 清单只是它安装时已知的历史，不能通过枚举其中最高版本断言线上没有新版。允许联网时，只从登记的官方公开仓库和正式 Release 确定最新标签，再取得该标签对应的 GitHub 自动生成源码 ZIP；只有已经证明公开 `main` 与该标签指向同一提交时，才可改用登记的“最新版 ZIP”短链接。如果当前请求已经提供唯一的本地升级包或解压树，先按同一来源、发布清单、路径与逐文件规则核验这份目标并直接使用；无法联网且没有唯一目标时，才请用户提供本地升级包。
3. Agent 告诉用户当前版本、已核验目标版本和来源。目标包自报的身份与发布边界只证明包内声明，不能单独冒充官方来源。目标版本如果登记了随包确定性 `prepare` 入口，该入口从登记的 GitHub HTTPS API 现场核对非草稿、非预发布 Release、固定标签提交、目标 Git 树、目标逐文件字节和发布清单；Agent 只把返回的 `userPreview` 原样展示。`prepare` 不替换实例，也不等于用户同意升级。用户确认后，`confirm` 只核对同次预览绑定的本地来源、目标树与实例没有漂移，不重复联网。
4. 用户选择：保留现状，或迁移升级。
5. Agent 自动执行、验证并报告；用户不需要操作终端。

正式 Release 的固定标签与内容才是这次安装来源。公开 main 前进不表示该 Release 失效；main 不再指向该标签时改用标签 ZIP，不能把开发中的 main 快照当成正式版。请求次数只限制联网开销，不是安装内容的正确性条件。

检查更新只在用户明确提出时进行。AI Carry 不后台联网、不自动下载，也不会因为发现新版本就强制升级。公开仓库不需要 GitHub 登录；如果用户指定其他仓库、附件或镜像，Agent 必须明确说明它不是登记的官方来源，并在读取或下载前让用户决定。

当前看板的正式支持目标是电脑端离线使用。升级后的界面验收以常见电脑窗口为准；手机窄屏布局不属于当前承诺，也不能因为手机端裁切就判定实例升级失败或停止其他能力。Agent 应直接向用户说明这一边界，不假装已经适配手机。

## 预览

Agent 读取当前 `instance/manifest.toml`、`core/upgrade/official-source.toml`、目标发布清单和 `core/ownership.toml`，将文件分为：

- 模板核心：可按清单替换或迁移。
- 实例身份与个人资产：默认保留。
- 正在使用的扩展接口：检查兼容范围。
- 本地私密和派生文件：不从升级包覆盖。

专业实例如果存在 `workspace/<扩展 ID>/extension.toml`，Agent 只按这份清单区分“随实例保留的正文、可重建内容、当前电脑本地内容和隐私集合引用”，不会在普通启动或升级预览里打开整个专业工作区。存在工作区但没有合法清单时，Agent 会原样保留并把它列为需要判断的冲突，不会猜测、执行或删除。

实例如果存在 `instance/components/registry.toml`，Agent 只定向读取登记清单，核对稳定接口、便携正文和当前电脑本地绑定。兼容组件原样保留；可选不兼容组件停用但不删除；必需组件不兼容时保持旧实例并停止切换。旧实例第一次接入 1.4 协定时，在隔离候选一次性完成全部活跃资源分类和登记，不在日常调用时逐项迁移。

如果现有实例已经有 `.assistant-private/catalog.toml`、`bindings.toml` 或私密正文，预览必须把它们列为“实例本地私密状态，原样保留”；模板只替换公开 Schema 与空模板，不创建、重置或猜测当前设备绑定。旧实例没有目录文件不构成升级失败：只有以后登记资料、命中 `private_refs`、导入导出或完整迁移时，才从当前相关引用渐进建立。

如果用户改过模板核心，先在隔离候选按实例兼容协定判断能否转换为已有扩展点、组件适配器或版本化迁移；原件保持不动。确实无法安全表达时，明确提示“该实例存在尚不能兼容迁移的核心修改”，保留旧实例并给出具体冲突，不让用户面对逐行合并工具。

预览还要检查一个旧版兼容问题：有些早期实例把完整个人档案直接写在 `instance/profile/README.md`，并让 `profile.user_preferences_ref` 指向它；新模板又把同一路径当作目录说明。发现这种结构时，预览必须明确显示“先把个人档案原样迁到 `instance/profile/approved-profile.md` 并更新引用，再替换目录说明”，不能把 README 直接覆盖。目标文件已有不同内容时显示冲突并停止自动迁移。

## 两个选择

- **保留现状**：跳过本次升级，实例继续工作。
- **迁移升级**：导出实例身份、偏好、记忆、能力、SOP、经验、延期卡、跨会话正式状态、长期治理卡的实例排期状态、不含秘密的宿主档案和批准过的进化成果；从新模板创建干净实例；按 Schema 迁入并重建路由地图、唤醒胶囊、非启动时间索引和看板快照。发布清单 `replace_instance_guides` 中精确列出的实例目录 `README.md` 使用新模板说明，避免旧规则和重复索引永久残留；同目录的所有其他文件、用户子目录、除固定说明外的实例档案与本地私密层继续保留。长期治理卡按稳定 ID 使用新模板的正文、频率与步骤，同时保留实例自己的启停、锚点、上次完成、下次到期、延后和触发修订；缺失、重复或 ID 变化时作为冲突预览，不能重置成模板空态。旧核心改动不自动带入，除非用户把它明确认定为个人资产或扩展。宿主档案保留的是历史观察，升级后在相关能力使用时重新验证。

升级前先确认用户实际能找到的看板入口已经存在，再创建临时回滚副本。Agent 在隔离目录组装候选，验证整棵目录、用户内容和平台特有元数据后才切换；多文件动作中断时整组恢复，不留下半新半旧。Windows 上普通候选优先继承目标父目录权限，不默认复制系统审核权限或所有者，也不因失败擅自提权。目标模板从固定发布内容或可信提交的允许文件集合组装，不能把开发目录里的 `node_modules`、Git 元数据、缓存或维护者私密文件因广义通配符一起复制。

隔离目录只证明候选文件与正式实例分开，不证明候选调用的本机运行时也分开。代表行为需要启动组件或专业扩展绑定的本机工具时，Agent 先用 `dashboard/scripts/copied-instance-runtime-boundary.mjs` 核对正式源根、候选根和本次明确使用的少量绑定文件。任何绑定回指正式源实例、未核验共享运行时或未解析动态路径时，不运行该工具，只把这项能力记为 `limited`，继续完成其他静态和无关行为检查；可以在候选中重绑副本专用运行时后重试。预检不得改写正式实例，用户也不需要手工运行它。

核心切换后，Agent 根据当前实例真实内容刷新两份一致的看板快照，不能用目标模板空白数据覆盖实例。快照失败只让看板进入待刷新并给出定向重试，核心升级和普通对话继续。刷新成功后再从稳定入口核对快捷方式、离线资源、匿名身份胶囊和页面标题；能读取地址栏时再核对精确落点。真正的核心身份或入口目标不一致才停止并恢复触碰过的核心文件。

升级后还会检查入口、地图目标、资产风险／授权／成熟度字段、实例交流方式与学习政策、长期治理卡正文版本与实例排期字段、跨会话控制修订、触发注册表、唤醒胶囊与时间索引聚合、宿主接入协议／Schema、私密目录按需入口、看板动作、快照、扩展接口和实例方向锁定。所有任务族路线必须是 `on-demand`；所有已激活、试用或待复核的正式记忆／能力／SOP／经验必须有类型一致、直达真实正文的实例路线。上述闭包先由确定性工具读取地图和 frontmatter 完成，不把全部正文、扩展工作区或私密目录塞进模型。旧实例缺少 `profile.guidance_mode` 时按 `balanced` 兼容读取，只在用户调整交流方式或清单因其他正式变化被迁移时写入；不得借补字段改变锁定方向。旧资产缺少新字段、旧实例缺少私密目录或没有专业工作区时都按保守默认值读取，只在相关内容被使用、修改、导出或复核时渐进补齐。Agent 自动完成升级验收并把结果交给用户确认后，才删除本次升级创建且不属于失败证据的临时回滚副本；用户自行生成的备份包、明确要求保留的现场和失败证据不处理。

核心切换后按 `core/protocols/UPGRADE_SESSION_ACTIVATION.md` 分开报告文件升级、看板刷新和当前会话采用。看板待刷新时先执行返回的定向命令；成功后再执行同次 `sessionReentryCommand` 核对回滚包、胶囊、manifest、双快照和代表路线。CLI 不能自行生成 `sessionActivated=true` 或 `behaviorAccepted=true`；宿主能观察真实重载与代表行为时再闭合，不能时说明下一次自然打开会采用新版。看板、会话或单项行为待接续都不回滚有效实例；只有核心文件或启动真源无效才回滚。

实例升级验收只使用这次升级返回的 `sessionReentryCommand`，再继续当前工作或完成一项与用户目标相关的无破坏代表行为。`dashboard/package.json` 中的 `check:*` 是母版开发、构建和发布工具，不属于已安装实例的升级门禁；不得在实例中枚举或运行整套开发检查，也不得因为缺少 `node_modules`、构建依赖或维护者环境把已经可用的实例判成升级失败。
